# ChooChooTracker ユーザーマニュアル

> [`docs/USER_MANUAL.md`](../USER_MANUAL.md) の日本語訳です。コミット `7c3ed6f` の英語版をもとに作成しています。内容に差異がある場合は、英語版が優先されます。
>
> **表記について。** アプリのインターフェースは英語です。そのため、画面名・メニュー名・フィールド名・ボタン名(Song、Chain、Phrase、Instrument、Table、Mixer、**Settings**、**EDIT**、**OPT**、**SELECT** など)、FX コード(`HOP`、`TBX`、`M1A` など)、モジュール名やエンジン名(ADSR、LFO、Braids、Plaits など)、ファイルの拡張子は、画面上の表示と照らし合わせやすいよう翻訳していません。

ChooChooTracker は、携帯ゲーム機向けの 8 トラックの音楽トラッカーです。

LSDj の定番のワークフローとナビゲーションを踏襲し、次のようなサウンドデザインの選択肢を備えています。

- AY チップのエミュレーション
- Mutable Instruments の Braids、Plaits、Plaits-Alt オシレーター(マルチモードフィルター付き)
- PCM サンプル、シングルサイクル波形、ウェーブテーブルオシレーター(マルチモードフィルター付き)
- aChChid: Open303 をベースにした多機能なアシッドシンセ
- Bogie: ネイティブの 12 モデル構成ドラムシンセ(マルチモードフィルター付き)
- MME: 2 オシレーター構成のマルチ変調シンセ(マルチモードフィルター付き)
- Sintered: ネイティブの 6 モデル構成の実験的デジタルドラムシンセ

## 1. インストールとファイル

### ArkOS / PortMaster

PortMaster で `choochootracker.zip` をインストールするか、展開したパッケージを本体の `ports` ディレクトリにコピーします。Ports メニューから **ChooChooTracker** を起動します。

### Miyoo Mini / Mini Plus (Onion OS)

MiyooPorts のアーカイブを SD カードのルートに展開し、その `Roms/PORTS/` フォルダーを Onion に既にあるフォルダーとマージします。コレクションを更新したあと、Ports メニューから **ChooChooTracker** を起動します。既存のインストールを置き換える前に、アプリの `projects/` フォルダーをバックアップしてください。

### Windows

`SDL2.dll` と `libwinpthread-1.dll` を同じディレクトリに置いて、`choochootracker.exe` を実行します。
**ALT + ENTER** でフルスクリーンの切り替えができます。ウィンドウはサイズ変更が可能で、
画像は元のアスペクト比を保ったまま拡大縮小されます。

### Web

ブラウザのページは、現在のトラッカーのテーマに従います。保存された設定(**Done** で確定した
カスタムキー割り当てを含む)は、このブラウザのストレージにすぐに書き込まれます。画面ロックやアプリの切り替えのあとは、
必要に応じてコントロールをタップするとオーディオが復帰します。**Restart audio** は、プロジェクトを破棄せずに
出力を開き直します。**Reload app** は、現在の作業を **Continue** に保存し、設定を保存し、
ブラウザのストレージの書き込みを待ってから再読み込みします。保存に失敗またはタイムアウトした場合は、
再読み込みが中止されます。持ち運び可能なバックアップには **Download .cct** を使ってください。ブラウザのストレージは
別途消去される場合があり、iOS でのコントローラーやオーディオのルーティングの復帰は
保証されません。

ブラウザ版は約 30 FPS で表示を更新し、コールバックの間にオーディオへより多くの時間を与えるため、
1024 フレームの固定オーディオバッファーを使います。以前に保存されたバッファー設定は自動的に調整され、
プロジェクトとその他の設定は保持されます。入力のポーリングとアプリのタイマーは、通常のペースのままです。

## 2. 操作

ChooChooTracker は、十字キー、アナログスティック 2 本、ボタン 7 個を備えたゲームパッドで最も快適に使えます。

| 論理コントロール | 携帯機のデフォルト | Windows のデフォルト |
|---|---|---|
| **[LEFT/RIGHT/UP/DOWN]** | 十字キー | 矢印キー |
| **EDIT** | A | X |
| **OPT** | B | Z |
| **PLAY** | Start | スペース |
| **SELECT** | Select | Shift |
| 変調軸 | 左右のスティック | ゲームコントローラーのスティック |
| **STICK LIVE** | L1 | Q |
| **MOTION RECORD** | L2 | W |
| **MOTION ERASE** | R2 | E |

割り当ては **Settings > Key mapping** で変更できます。PortMaster では、割り当てを選ぶのに使ったボタンを離してから、新しいボタンを押してください。
再割り当ては **Done** で保存し、そのあとボタンを離してから Settings での操作を続けます。
デスクトップのレイアウトのデフォルトは、QWERTZ の地域でのみ QWERTZ を使います。ポーランド語のキーボードは
標準の QWERTY のデフォルトのままです。

Windows、Web、Android でもゲームコントローラーが使えます。Android では、
ゲームパッドが接続されていないときにタッチコントロールが自動的に表示されます。縦向きでは
トラッカーの下に、正方形の十字キー、A/EDIT、B/OPT、START/PLAY、
SELECT/SHIFT の各コントロールが並び、その下に 2 本の変調スティックと
一時的な REC/DEL コントロールを備えた Live/Motion セクションが別に表示されます。横向きでは、十字キーが左、
アクションボタンが右に配置されます。Android のプロジェクトとサンプルはアプリ専用のままです。
`.cct` プロジェクトと `.wav` サンプルのインポートや、WAV エクスポートの保存先の選択には、
Android のファイルピッカーを使います。

### ナビゲーション

- **[UP/DOWN/LEFT/RIGHT]** でカーソルを動かします。
- **SELECT + [DIRECTION]** を押し続けて、画面間を移動します。
- **SELECT + [LEFT/RIGHT]** は、Instrument Pool のように、ブランチページから隣の MSCPIT 画面へ抜けることもできます。
  Project/Settings(Settings のサブメニューを含む)は
  Mixer/Chain へ、Groove は Chain/Instrument へ、Modulation/Insert FX は
  Phrase/Table へ、AY Wavetable は Instrument/Table へつながります。左端では、Reverb/Delay は
  SELECT + LEFT で Mixer に戻ります。既存の縦方向のナビゲーションは変わりません。
- **OPT + [DIRECTION]** を押し続けると、画面ごとのナビゲーションになります。
- 値の上では、**EDIT + [LEFT/RIGHT]** で細かく、**EDIT + [UP/DOWN]** で大きく変更できます。
- Modulation の **Destination** では、**LEFT/RIGHT** で利用可能なデスティネーションを直接切り替えられます。**EDIT** をタップすると、グループ分けされたメニューが開きます。
- **EDIT** をタップすると、値を入力したりコマンドを実行したりします。
- **EDIT** を 2 回タップすると、対応している場所で新しいチェーン、フレーズ、インストゥルメントを作成します。
- 方向を押し続けると、Settings で設定した遅延のあとに繰り返されます。

### 選択とクリップボード

- **SELECT + OPT** で選択モードに入り、便利な選択範囲を順に切り替えます。
- **[DIRECTION]** で範囲を広げます。
- **OPT** で選択範囲をコピーします。
- **OPT + EDIT** で切り取ります。
- **SELECT + EDIT** で貼り付けます。
- **EDIT + [DIRECTION]** で、選択したセルをまとめて編集します。

Phrase 画面では、選択範囲があるとき、ノート列をリズムパターンで埋められます。

- **OPT + LEFT** は、選択範囲のノートセルを固定の 16 ステップのパターンで埋め、
  押すたびに次のパターンへ進みます。最後のパターンのあとはノートが消去され、
  サイクルが最初から始まります。パターンは絶対的なフレーズの行に合わせて配置されるため、
  部分的な選択では、その範囲に入るステップだけが入力されます。
- **OPT + RIGHT** は、選択範囲のノートセルを 3〜8 個のノートのランダムなパターンで埋めます
  (7 個と 8 個は出にくくなっています)。**OPT** を押し続けている間、無限に繰り返されます。
- **OPT + UP** は、選択範囲にすでに置かれているノートを変化させます。押すたびに
  そのうち 1〜3 個を選び、それぞれを 1 オクターブ以内のランダムな量だけずらします
  (小さなずれのほうが極端なずれより起こりやすくなっています)。**Note Lock** がオンのときは、
  ずらしたノートがスケールに戻されます。**Slice** がオンの Sampler インストゥルメントは
  半音階のままです。何も消去されません。8 回目の押下で、サイクル開始時に選択範囲が
  持っていたノートが復元され、そのあとサイクルが最初から始まります。
- ボリューム列だけを含む選択範囲(ノート、インストゥルメント、FX のセルがない)での **OPT + UP** は、
  変化ではなくベロシティのランダム化になります。1 回目は Minimal パターン(各ボリュームが最大
  +-20 ずれる)、2 回目は Medium(最大 +-50)、3 回目は Random(完全に
  ランダムな値)、4 回目はサイクル開始時に選択範囲が持っていたボリュームを復元します。
  **OPT** を離すと、サイクルは Minimal に戻ります。
  ボリュームのない行には手を加えません。
- **OPT + DOWN** は、選択範囲内のスライス済み(sliced)Sampler インストゥルメントの置かれたノートを、
  半音階の連なりに広げます。各インストゥルメントの最初のノート(シーケンサー上で最も高いもの)は
  値を保ち、そのインストゥルメントの以降のノートは、それぞれ直前より半音ずつ上がります。
  同じノートの積み重ねが、連続したスライスのトリガーに変わります。複数のスライス済み
  インストゥルメントは、それぞれの最初のノートから独立して広がります。スライスしていない
  インストゥルメントのノートには手を加えず、結果がプロジェクトのスケールに
  合わせられることもありません。広げる処理が最後に書いたノートが、ノート入力で最後に使ったノートになるため、
  手で続きを入力すると次のスライスから再開されます。スライス済みのインストゥルメントだけを含む選択範囲では、
  押すたびに広がります。スライスしていないノートも含まれる場合は、1 回目の押下で広げる処理が行われ、
  2 回目以降はランダムアルペジオがそれらのノートを引き継ぎます。
- スライス済みインストゥルメントのノートを含まない選択範囲での **OPT + DOWN** は、
  すでに置かれているノートに対するランダムアルペジエーターです。CRD パレットからコードが選ばれます。
  1〜2 ノートの選択範囲では 3 ノートのコード、3 ノートでは 3 ノート以上のコード、
  4 ノート以上では任意のコードです。ルートは、選択範囲の音域内にあるプロジェクトのスケール上のランダムなノートになり
  (スケールがオフ、またはトラックが除外されている場合は任意の半音階のノート)、
  構成音は CRD の再生と同様にスケールへクオンタイズされます。押すたびに、コードが置かれたノートに
  再配分されます。ランダム、低い順、高い順、そして上下の順です。5 回目の押下で元のノートが復元され、
  次の押下で新しいコードが選ばれます。アルペジオが有効な間は、コード名がステータスバーに表示されます。
  ノートが追加や削除されることはなく、**OPT** を離すと処理全体がリセットされます。
- 埋める操作は、押すたびに書き込む前に選択範囲のノートを消去し、置かれたノートには
  最後に使ったインストゥルメントが付きます。**OPT** を離すと、サイクルは最初のステップに戻ります。
- 選択範囲があり、ほかのメッセージが表示されていないとき、ステータスバーは 2 秒ごとに
  これらの組み合わせのリマインダーを切り替えて表示します。`EDIT + DIR =
  batch note edit`、`Double-tap EDIT: resample selection`、`OPT + LEFT =
  pattern fill`、`OPT + RIGHT = random fill`、`OPT + UP =
  mutate/randomize velocity`、`OPT + DOWN = random arp/slice spread` です。
  選択モードに入る、または出ると、切り替えが最初からやり直されます。操作のメッセージが出ると、
  期限が切れるまでヒントはそのメッセージに置き換わります。

### 再生

- **PLAY** はカーソル位置から再生を始めます。もう一度押すと停止します。
- 再生中にノート、インストゥルメント、チェーンを編集できます。変更は次のシーケンサーのティックで反映されます。
- **SELECT + PLAY** は、Song 画面以外で使うと、すべてのトラックを開始します。
- **EDIT + PLAY** は、Instrument Pool からインストゥルメントを試聴します。

## 3. ソングの構造と画面マップ

**SELECT + [DIRECTION]** を押し続けて、画面間を移動します。

メインのナビゲーション行は次のとおりです。

<pre>
R P   G M
<strong>M S C P I T</strong>
D S     P W
</pre>

中央の行:

- **M**: Mixer(Reverb、Delay へ分岐)
- **S**: Song(Project、Settings へ分岐)
- **C**: Chain
- **P**: Phrase(Groove へ分岐)
- **I**: Instrument(Modulation と Instrument Pool へ分岐)
- **T**: Table(AY Wavetable エディターへ分岐)

上の行:

- **R**: Reverb
- **P**: Project
- **G**: Groove
- **M**: Modulation

下の行:

- **D**: Delay
- **S**: Settings
- **P**: Instrument Pool
- **W**: AY Wavetable エディター

ChooChooTracker のソングは、次の階層構造になっています。

```text
Song -> Chain -> Phrase row -> Note + Instrument + FX
```

ソングには 8 つのトラックがあります。各トラックはチェーンの並びを持ち、各チェーンはフレーズの並びを持ちます。フレーズは 16 ステップのノートの並びです。ノートは、音程、インストゥルメント、ベロシティ、最大 3 つのトラック FX を持ちます。インストゥルメントは、音を出すものです。

### オプションの 16x24 フォントと NostromoAmberDa2

Settings → Load font → fonts/Pixel16x24 には、TechMonoAudit(Share Tech Mono から変換)、Departure Mono、Spleen、Cozette が入っています。いずれも、640×480 のディスプレイ向けに、印字可能な ASCII 文字の全セットを 16×24 のセルで提供します。ピクセルで作られたフォントは、元のピクセルまたは余白付きの整数倍拡大を保ちます。Cozette は、13 ピクセルのインク高さを 2 倍にするとセルをはみ出すため、小さいままです。NostromoAmberDa2 テーマは、Settings → Edit color theme → Load から使えます。Nostromo のアンバーの背景と案内テキストを保ちつつ、メインのテキストは赤、値はより暗いオレンジ、カーソルはティールになっています。これらの素材を読み込んでも、選択中のフォントやテーマは変わりません。出典とライセンスについては、付属の README.txt を参照してください。

### Project ページの余白

Project ページでは、アプリのバージョンが独立した行に置かれ、Load、Save、New、Export、Manage がプロジェクトのメタデータと空行で区切られます。カーソル位置とタッチ領域は表示されるフィールドに従います。プロジェクトの設定とファイル操作は変わりません。

### オーディオ表示のテレメトリ

オーディオの表示には、UI が所有する、最終ミックスと各トラックの寄与のスナップショットが使われます。トラックのサンプルとステレオのピークは、トラックレベルと tilt のあと、共有エフェクトのリターンとマスターゲインの前で取得されます。モニタリングはオーディオ信号を変更しません。オーディオコールバックは、ロックやメモリ確保なしで固定サイズのスナップショットを公開します。表示される履歴は約 21 ms 分です。

### 常時表示の波形

Graphics → Persistent waveform は、デフォルトでは OFF です。EDIT をタップするか EDIT + 方向キーで切り替えられ、この選択はアプリの設定として保存されます。OFF では、フル高さのページと既存のインストゥルメント波形プレビューに戻ります。有効にすると、編集ページの上に 2 行の波形が表示され、最終ミックスをモノラルに合算したものを示します。Instrument ページと Modulation ページには、選択中のインストゥルメントを使うトラックの出力が表示されます。複数のトラックが使っている場合は、選択中の Song トラックが優先されます。Project、Settings、ウェーブテーブル、ポップアップは、フル高さのままです。リストは残りの行の中でスクロールします。Instrument のフッターには ADSR/サンプルのプレビューが残り、Modulation のフィールドは、すべてのコントロールが操作できるよう詰めて表示されます。タッチ領域は、どちらの波形モードでも表示されるフィールドに従います。

### 再生ピアノ

コードで描かれたピクセルのピアノが、右側の 8 つのトラック行の下にあり、鳴っているピッチクラスを 1 オクターブに折りたたんで光らせます。コードのノートも含まれ、ミュートや停止したトラックは反映されません。輪郭にはテーマの値の色、アクティブなすべての鍵には波形の色が使われます。待機中の鍵は暗い塗りと控えめな影で表示されます。グリッドは整数倍のスケーリングと固定幅の枠線を使います。ピアノは再生のインジケーターであり、ノート入力のコントロールではありません。ポップアップと Wavetable エディターは、この領域の自分のコンテンツをそのまま保ちます。

### Mixer のメーター

Mixer には、各トラックの PAN と tilt のあと、共有エフェクトとマスターゲインの前の、並んだ **L/R** のピークバーが表示されます。メーターの範囲は -48〜0 dBFS で、更新の合間に減衰します。下側と中間の帯域にはテーマの色が使われ、最上段の帯域はフルスケール付近で鮮やかな赤になります。

## 4. Song、Chain、Phrase

### Song

Song 画面には 8 つの列があり、オーディオトラック 1 つにつき 1 列です。各セルはチェーンを参照します。ソングは最大 256 行(`00-FF`)を持てます。

トラックは左から右へ、そのチェーンは縦方向に並びます。各トラックは独立しており、チェーンは 1〜16 個のフレーズを持てるため、トラック同士がずれることがあります。揃えたままにしたいならチェーンをそのように設計し、トラックがそれを必要とするなら、そのままずれていくに任せてください。

空のフレーズ用にチェーンを 1 つ確保しておくのが一般的で、たいてい `00` か `FE` です。

空行で区切られたセクション、つまり「島」を作ることで、1 つのプロジェクトに複数のサブソングを持たせられます。

#### Live Mode

**OPT** を 2 回タップすると、Live Mode に入る、または出ます。Song のタイトルは `LIVE` に置き換わります。Live Mode では、トラックが停止しているとき、**PLAY** は選択中のチェーンをそのトラック上で開始します。再生中のトラックでは、選択中のチェーンを次のチェーンの境界にキューします。**PLAY** を 2 回押すと、次のフレーズの境界での緊急の切り替えになります。空の Song セルを選択している場合は、代わりにクオンタイズされた停止がキューされます。`+` はキュー済みのチェーン、`!` は緊急のチェーン、`-` はキュー済みの停止を示します。

複数の列にまたがる 1 つの Song 行を選択すると、それらのトラックをまとめてキューまたは停止できます。複数行の選択は意図的に拒否されます。Song の範囲ループが有効な間は、Live のキューは消去されます。Live はパフォーマンス用のモードで、プロジェクトには保存されません。

#### 操作

- **OPT + [UP/DOWN]**: 16 位置上または下へジャンプ
- 範囲を選択して **SHIFT + EDIT**: 元のフレーズを保ったまま、チェーンを浅くクローン
- 範囲を選択して **SHIFT + EDIT** を 2 回タップ: チェーンとそのフレーズの両方を深くクローン
- 範囲を選択して **EDIT + [UP/DOWN]**: 選択範囲を上または下へ移動
- **OPT** を 3 回タップ: 視覚的な整理のためのハイライトを追加または削除
- **OPT + SHIFT**: 現在のトラックまたは選択した列をミュート(ミュートを保持するには、先に **OPT** を離します)
- **OPT + PLAY**: 現在のトラックまたは選択した列をソロ(ソロを保持するには、先に **OPT** を離します)
- **OPT + [LEFT/RIGHT]**: 現在のトラックの左または右にあるすべてのトラックをソロ
- 範囲を選択して **EDIT** を 2 回タップ: BOUNCE TO SAMPLE 画面を開く(下の Bounce を参照)

#### Bounce

Song の行と列の範囲を選択して **EDIT** を 2 回タップすると、BOUNCE TO SAMPLE 画面が開きます。バウンスには選択したすべてのトラックが含まれます。最初のチェーンが選択範囲の後ろで始まるトラックは、無音で待機して最初のチェーンの頭から加わるため、ファイルには選択したすべてのトラックのチェーンが入ります。

この画面には次の項目があります。

- **File name**: 文字キーボードで編集します。画面を開くと、次に空いている連番(`001`、`002`、...)がここに提案されます。これは、エクスポートフォルダーにまだ `.wav` ファイルが存在しない最初の番号です。自由に編集できます。名前はそのまま使われます。その名前のファイルがすでに存在する場合は、既存のファイルを上書きしないよう、接尾辞 `_001`、`_002`、... が付きます。カウンターは、プロジェクトを読み込む、または作成するとリセットされます。
- **Sample rate** と **Bit depth**: エクスポート画面と同じオプション
- **Include in a sample name**: **Start** を押したときに、ファイル名の先頭にコンテキストのタグを付ける 3 つのチェックボックス(すべてデフォルトでオフ):
  - **[BPM]** - プロジェクトの現在のテンポ(例: `[120]`)
  - **[Key]** - プロジェクトのルート音とスケール(例: `[Cmaj]`、`[F#min Pent]`)
  - **[Bars:Beats:16ths]** - レンダリングされたバウンスの長さ。1 フレーズは 1 小節(16 分音符 16 個)で、1 拍は 16 分音符 4 個です。完全なフレーズは小節数のみ(例: `[2]`)、部分的なフレーズは `[0:2]`(2 拍)や `[0:1:3]`(1 拍と 16 分音符 3 個)のように表示されます。複数トラックのバウンスでは、最も長いトラックで決まります。拍の途中で終わる選択範囲は、16 分音符 1 個分短く数えられます。選択した最後の行がカットポイントになるため、そのノートオフは直前の 16 分音符の終わりに来ます。
  - タグは、ファイル名の前に `[BPM][Key][Length]` の順で付けられます。
- **Start**: 選択範囲をエクスポートフォルダーの WAV ファイルにレンダリング(Project 画面の *Export location* を参照)
- **Cancel**: バウンスせずに戻る

バウンスのレンダリング中は、**OPT** でキャンセルできます。バウンスが完了またはキャンセルされると、バウンス元の画面に戻ります。

デスクトップでは、key jazz により、ここでも 16 進インデックスの直接入力、Phrase と同じ
Shift+矢印キーでの選択、Delete/Backspace/Insert、Ctrl+C/X/V が使えます。
[Key jazz](#key-jazz-デスクトップのみ) を参照してください。

### Chain

チェーンは、16 ステップのフレーズの順序付きリストで、トランスポーズを指定できます。最大 16 個のフレーズを持て、同じフレーズを複数回登場させることもできます。2 列目はトランスポーズを半音単位で設定します。

プロジェクト内で再利用されているチェーンの横には、アスタリスク(`*`)が表示されます。チェーンは Song 画面からクローンできます。

#### 操作

- **OPT + [LEFT/RIGHT]**: トラック間を移動
- **OPT + [UP/DOWN]**: 現在のトラック内のチェーン間を移動
- 範囲を選択して **SHIFT + EDIT**: フレーズをクローン
- 範囲を選択して **EDIT** を 2 回タップ: 現在のトラックの、選択したチェーンの行の BOUNCE TO SAMPLE 画面を開く(Song の Bounce を参照)

デスクトップでは、key jazz により、ここでも 16 進インデックスの直接入力が使えます。
[Key jazz](#key-jazz-デスクトップのみ) を参照してください。

### Phrase

フレーズは、従来のステップシーケンサーにおける、トラックのパターンです。

フレーズは 16 ステップの長さで、1 ステップにつき 1 行です。各行には、ノート、インストゥルメント、`00` から `7F` のボリューム、FX 列が入ります。ノートは、`C-4`(音名とオクターブ)のようなトラッカー表記を使います。

ノートを止めるには、`NOTE OFF` を挿入するか、ノートキル FX を使うか、インストゥルメントを指定せずに別のノートを鳴らします。

チェーンに複数のフレーズが含まれているときは、Phrase 画面は連続したパターンエディターのように動作します。行 `F` より下、または行 `0` より上へ移動すると、チェーンの次または前のフレーズが開きます。

プロジェクト内で再利用されているフレーズの横には、アスタリスク(`*`)が表示されます。フレーズは Chain 画面からクローンできます。

FX セレクターには、よく使うコマンドと、その行のインストゥルメントが対応するコマンドが表示されます。これにより、エンジン固有のコマンドを並べた長いグローバルリストを避けられます。ChooChooTracker は ChipNomad よりも多くの FX に対応しています。

### 操作

- 空のノート上で **OPT + EDIT**: `NOTE OFF` を挿入
- FX 名の列で **EDIT + [UP/DOWN]**: FX 選択画面を開く
- **OPT + [LEFT/RIGHT]**: トラック間を移動
- **OPT + [UP/DOWN]**: 現在のチェーン内のフレーズ間を移動
- インストゥルメント列で範囲を選択して **SHIFT + EDIT**: インストゥルメントをクローン
- 範囲を選択して **EDIT + [UP/DOWN]**: フレーズの行をローテーション
- 範囲を選択して **EDIT** を 2 回タップ: 現在のトラックの、選択したフレーズの行の BOUNCE TO SAMPLE 画面を開く(Song の Bounce を参照)

### Key jazz (デスクトップのみ)

Phrase 画面で **Esc** を押すと、QWERTY のピアノ風のノート入力モードである key jazz を
オン/オフできます([m8c](https://github.com/laamaa/m8c) と同様)。

- `Z S X D C V G B H N J M` と `Q 2 W 3 E R 5 T 6 Y 7 U I 9 O 0 P` で、2 オクターブ以上にわたって
  半音階でノートを入力します。各キーの物理的な位置を使うため、AZERTY、QWERTY、QWERTZ の
  キーボードで同じ配列になります。
- キーを押すたびに、現在の行にノートが書き込まれ、次の行へ進みます。
- `[` / `]` でオクターブをずらします。
- **Shift + 矢印キー** で、行と列の範囲を選択します。そのあと矢印キーだけを押すと、
  選択が解除されます。
- **Ctrl+C** / **Ctrl+X** で、選択した列をコピーまたは切り取ります。何も選択していない場合は、
  現在の行のノート/インストゥルメント/ボリュームが対象です。**Ctrl+V** はカーソル位置に貼り付けます。
- **Delete** は、行全体(すべての列)を削除し、フレーズの残りを上に詰めて隙間を埋めます。カーソルは
  同じ行に留まります。
- **Backspace** は、現在の列のみ(選択範囲がある場合は選択範囲の列)でカーソル下の要素を削除し、
  それより下にあるものを上に詰めて隙間を埋め、テキストエディターのようにカーソルを 1 行戻します。
- **Insert** は空行を挿入し、フレーズの残りを下へ押し下げます。
- **Ctrl+S** はプロジェクトを保存します。key jazz の外では、Ctrl+S は何もしません。
- もう一度 Esc を押すと、key jazz がオフになります。

key jazz がオンの間は、Phrase 画面のノートキーを完全に占有します。同じキーを共有する
Edit/Opt/Motion のショートカットも含まれます。それらを再び使うには、Esc で key jazz をオフにしてください。

key jazz は、Esc で個別に切り替えられる形で、次の画面でも動作します。

- **Song** と **Chain**: Up/Down で増減する代わりに、チェーンやフレーズの 16 進インデックス
  (`0-9`、`A-F`)を直接入力します。セルに最初に入力した数字はその値を置き換え、
  移動せずに入力した続きの数字はその中へ送り込まれます(「3」に続けて「F」と入力すると 3F になります)。Song では、
  **Shift+矢印キー** で範囲を選択し、**Delete** で行全体を削除して残りを上に詰め、**Backspace** で
  現在/選択した列を削除してその下を上に詰め、**Insert** で空行を挿入し、
  **Ctrl+C**/**Ctrl+X**/**Ctrl+V** で選択した行(何も選択していなければ現在の行)を
  コピー/切り取り/貼り付けします。これらは、Phrase 画面と同じ構造編集のショートカットです。
  これは Shift を占有するため、ここで key jazz が有効な間は、Shift+Right/Up で
  Chain/Project へジャンプできなくなります。それらのショートカットを戻すには Esc を押してください。
- **テキストフィールドのあるすべての画面**: 画面上の仮想キーボードを使う代わりに、
  キーボードから直接入力します。これには、Project のファイル名、タイトル、作者、インストゥルメント名、
  カラーテーマ名、ピッチテーブル名、バウンスのファイル名、名前ダイアログ(名前の入力、
  フォルダーの作成)が含まれます。Backspace は通常のテキストフィールドと同様に動作し、Shift で
  大文字を入力します。Esc はこれらすべての画面で同時に切り替わり、key jazz がオフのときは、
  仮想キーボードが通常どおり開きます。

## 5. Instruments

すべてのインストゥルメントには、いくつかの共通パラメーターがあります。

- インストゥルメントのタイプ
- 名前(最大 15 文字)
- デフォルトのテーブル速度(テーブルの 1 行あたりのティック数)
- トランスポーズのオン/オフ

各インストゥルメントには、`00-7F` の範囲で同じ番号のデフォルトテーブルがあります。これらを補助テーブルとして使うこともできますが、補助テーブルを `80-FE` の範囲に置くと、競合や混乱を避けられます。テーブルは、ChooChooTracker の主要なサウンドデザインツールの 1 つです。

### 操作

- **OPT + [LEFT/RIGHT]**: インストゥルメント間を移動
- **EDIT + PLAY**: インストゥルメントを試聴
- **SHIFT + OPT**: インストゥルメントをコピー
- **SHIFT + EDIT**: インストゥルメントを貼り付け

### AY Classic、AY Plus、AY Sample

これらは、ChipNomad 由来のオリジナルの AY/YM エンジンです。AY Classic は、ハードウェアに近い形でトーン、ノイズ、エンベロープのコントロールを提供します。AY Plus は、ソフトウェアオシレーターとより豊かな変調を追加します。AY Sample は、AY 方式のボリュームレベルを通してサンプルを再生するもので、Sampler エンジンとは別物です。

#### AY Classic

ChipNomad `v1.0.0` 由来のレガシーなインストゥルメントタイプです。新しい AY Plus インストゥルメントのほうが、より多くの機能を備えています。

AY Classic インストゥルメントには、次のパラメーターがあります。

- Mixer: トーンのオン/オフ、ノイズのオン/オフ、エンベロープシェイプ(`0-F`)
- Volume: ソフトウェアで生成される ADSR エンベロープ
- 自動エンベロープ周期: オン/オフ、比率は `1:1` から `F:F`

Settings の **AY Quality** は、AY/YM のレンダリングにのみ影響します。Braids、Plaits、Sampler の品質は変わりません。**Sample dithering** は、AY Sample の量子化に適用されます。

チップの詳細は、[ChipNomad の AY-3-8910 のドキュメント](https://chipnomad.org/chips/ay-3-8910/)を参照してください。

#### AY Plus

AY Plus は、従来のシンセの考え方を、AY-3-8910/YM2149F のサウンドデザインに適用します。AY は 5 つのオシレーターを持つシンセサイザーと考えられます。

- 矩形波のトーンオシレーター 3 つ
- ノイズオシレーター 1 つ
- オシレーターとしても使える振幅エンベロープジェネレーター 1 つ

このモデルでは、各インストゥルメントは、トーン、ノイズ、エンベロープの 3 つのハードウェアオシレーターを持ちます。AY Plus は、4 つ目のソフトウェアオシレーターを追加します。プロジェクトのティックレートより速く AY のレジスターを更新すると、サウンドデザインの幅がさらに広がります。AY の仕組み上、オシレーターはリング変調でミックスされます。ピッチオフセット、デチューン、オシレーターの組み合わせをいろいろ試して、どんな音になるか確かめてください。

各トーナルオシレーターは、ピッチオフセットとファインチューンオフセットで独立してチューニングできます。

ソフトウェアオシレーターのタイプとそのパラメーター:

- Pulse - パルス幅を制御できる矩形波
  - FM Depth - シンプルな FM の深さ
  - Pulse width - 全範囲は `00-FF` で、ステップ数は Project 画面で設定します
  - Pulse low - 高い値が常に `15` である、繰り返されるペアの低い値を制御します
- Sync Tone - トーンオシレーター用のハードシンク効果
  - FM Depth - シンプルな FM の深さ
- Sync Env - エンベロープオシレーター用のハードシンク効果
  - FM Depth - シンプルな FM の深さ
  - Pulse width - エンベロープのペアにおける 2 つのシェイプの長さの比
  - Envelope Pair - 切り替える 2 つのエンベロープシェイプ
- Wavetable - Wavetable 画面で編集する 32 ステップのウェーブテーブル
  - FM Depth - シンプルな FM の深さ
  - Wavetable index
- Tone FM - トーンオシレーター用の、シンプルな FM 風の効果
  - FM Depth - トーンの FM の深さ
- Env FM - エンベロープオシレーター用の、シンプルな FM 風の効果
  - FM Depth - エンベロープの FM の深さ

Pulse と Wavetable のソフトウェアオシレーターは、Envelope オシレーターと併用できません。Envelope オシレーターは自動的にオフになります。

シンプルな FM は、低い周期値と高い周期値の 2 つの間を素早く切り替えます。これは、矩形波を FM モジュレーターとして使うのに似ています。Pulse、Sync Tone、Sync Env、Wavetable は、FM のキャリアとモジュレーターの間に `1:1` の比率を使います。Tone FM と Env FM は、ソフトウェアオシレーターのピッチオフセットを通じて、ほかの比率を模倣できます。

#### AY Sample

`8 ビット`、`16 ビット`、`24 ビット`、`32 ビット` のモノラルまたはステレオの WAV ファイルを読み込めます。これらは `8 ビット` に変換され、`16 KB` に切り詰められます。この制限は、ZX Spectrum の RAM ページのサイズに合わせたものです。

AY は、ボリュームレジスターへの高速な書き込みでサンプルを再生します。出力は単極性なので、よりクリーンに再生するには、サンプルを「ゼロまで持ち上げる」必要があります。これにより、サンプル末尾のクリックノイズがなくなり、静かな余韻が改善されます。

AY の DAC は `4 ビット` の分解能で、ボリュームの目盛りが非線形のため、`8 ビット` のサンプルは再生時に `4 ビット` に変換されます。Settings の Sample dithering オプションで、体感的なビット深度を改善できます。ディザリングは、ZX Spectrum や Atari ST のようなレトロなプラットフォームでは現実的ではないため、実機向けに作る場合や、ザラついたローファイな音を狙う場合は、オフのままにしてください。

サンプルは、AY Plus のもう 1 つのソフトウェアオシレーターのように動作しますが、追加のパラメーターがあるため、独立したインストゥルメントタイプとして扱うほうが簡単です。

サンプルのパラメーター:

- Sample rate - サンプルをネイティブのレートで再生すると、`C-4` になります
- Sample start
- Sample length
- Sample loop start
- Sample pitch offset
- Sample fine pitch offset

Tone と Noise のオシレーターのセクションは、AY Plus と同じです。AY の仕組み上、すべてのオシレーターはリング変調でミックスされます。

### Braids

Braids は 47 種類のシンセシスモデルを備えています。主なコントロールは次のとおりです。

- **Model**: オシレーターまたはシンセシスのアルゴリズム
- **Timbre** と **Color**: モデルによって異なるマクロパラメーター
- **Filter**: 追加の LP/BP/HP フィルター(スロープ `12` または `24 dB`、カットオフ、レゾナンス)
- **ADSR**: アタック、ディケイ、サスティン、リリース

**Model** をタップすると、カテゴリー別のモデルリストから選べます。

| カテゴリー | モデル |
|---|---|
| Analog | `00 CSAW`, `01 MORPH`, `02 SAW-SQUARE`, `03 SINE-TRI`, `04 BUZZ`, `05 SQUARE-SUB`, `06 SAW-SUB`, `07 SQUARE-SYNC`, `08 SAW-SYNC` |
| Multi Osc | `09 TRIPLE-SAW`, `10 TRIPLE-SQR`, `11 TRIPLE-TRI`, `12 TRIPLE-SINE`, `13 TRIPLE-RING`, `14 SAW-SWARM`, `15 SAW-COMB`, `16 TOY` |
| Filter / Voice | `17 FILTER-LP`, `18 FILTER-PEAK`, `19 FILTER-BP`, `20 FILTER-HP`, `21 VOSIM`, `22 VOWEL`, `23 VOWEL-FOF`, `24 HARMONICS` |
| FM / Chaos | `25 FM`, `26 FEEDBACK-FM`, `27 CHAOTIC-FM` |
| Physical | `28 PLUCKED`, `29 BOWED`, `30 BLOWN`, `31 FLUTED`, `32 STRUCK-BELL`, `33 STRUCK-DRUM` |
| Drums | `34 KICK`, `35 CYMBAL`, `36 SNARE` |
| Wavetables | `37 WAVETABLES`, `38 WAVE-MAP`, `39 WAVE-LINE`, `40 WAVE-PARA` |
| Noise / Granular | `41 FILTER-NOISE`, `42 TWIN-PEAKS`, `43 CLOCK-NOISE`, `44 GRAN-CLOUD`, `45 PARTICLE`, `46 DIGI-MOD` |

#### パラメーター

Timbre と Color は、選択したモデルによって異なります。モデルの全リストと詳細は、Mutable Instruments の Braids の元のマニュアルを参照するか、耳で試してください。

#### VCF と VCA

Braids は、ChooChooTracker 標準のマルチモードフィルターと ADSR エンベロープに信号を送ります。

#### 設定

Braids のグローバル設定は、アプリの設定にあります。

- **BITS**: 出力の分解能を下げます
- **DRFT**: オシレーターのピッチの不安定さを加えます
- **SIGN**: 元の Braids の波形の不完全さを再現するアルゴリズムです

### aChChid

**aChChid** は、Open303 をベースにしたモノフォニックのアシッドベースエンジンです。`Square` と `Saw` は、TB-303 本来のオシレーター、フィルター、エンベロープ、アクセントの挙動を使います。`Braids` はオシレーターだけを置き換え、そのあとは同じ 303 のフィルターとアンプの経路を通ります。Fine tune の代わりに、Model、Timbre、Color、Shaper を備えています。Shaper は、ソフトなサチュレーションからウェーブフォールディングへと変化します。aChChid は、ChooChooTracker の統合ポストフィルターや ADSR を使いません。

Cutoff と Decay は対数的に編集されます。**EDIT + LEFT/RIGHT** は音楽的なコントロールステップ 1 つ分、
**EDIT + UP/DOWN** は 16 ステップ分動きます。Cutoff の範囲は 200 Hz〜20 kHz、Decay の範囲は 200 ms〜2 s です。

ノートのボリューム列の `F` は、アクセントをトリガーします。通常のノートは、半ステップ分のゲートを使います(デフォルトの 6 ティックのグルーヴでは 3 ティック)。`ASL` は、303 のエンベロープを再トリガーせずに、直前のピッチからそのノートへスライドします。直前のゲートを自動的に保持し、`ASL 00` では `60 ms` のグライドになります。`ATY` は、現在のステップ全体にわたってノートを開いたままにします。`ASL` のないノートは、常に再トリガーされます。変調のデスティネーションには、Decay と Accent に加え、Braids 波形モードでの Timbre と Color が含まれます。

### Bogie

**Bogie** は、ネイティブのワンショットドラムシンセです。トラッカーのノートがピッチを、トラッカー/インストゥルメントのボリュームがレベルを決めます。各トリガーに固有の内部ディケイがあるため、ADSR ページはありません。12 のモデルがあります: `Kick`、`Snare`、`Hat`、`Clap`、`Tom`、`Rim`、`FM`、`Noise`、`Cowbell`、`Cymbal`、`Shaker`、`Clave`。

6 つのマクロは、**Decay**、**Tone**、**Sweep**、**Noise**、**FM**、**Drive** です。ラベルは、役に立つ場面では変わります(たとえば、Kick の Noise は `Click`、Cowbell の FM は金属的なクロス変調です)。すべてのマクロはすべてのモデルで有効ですが、音楽的な役割はモデルによって変わります。Sweep は、ピッチ、バーストの間隔、金属的な広がりを変化させることがあります。FM は、クロス変調、金属的なレイヤー、リング風の倍音を加えることがあります。各範囲の下半分は一般的なドラムの音向けで、上半分は意図的により広い音色の変化とよりシンセティックな結果を開きます。

どのモデルでも、共有の LP/BP/HP マルチモードフィルターを使えます。キャラクターは Clean、Classic、Aggro、Acid、スロープは `12`/`24 dB`、カットオフとレゾナンスがあります。Bogie は、アクティブなすべてのマクロに加え、Volume、Pitch、Cutoff、Resonance を、変調とモーションレコーディングのデスティネーションとして対応しています。Cowbell で鋭い phonk 風のアタックを作るには、短い Decay を使います。より硬く金属的なベルにするには、FM を上げます。

Modulation 画面では、ソース上で **EDIT** を押してファミリー(Envelopes、LFO、Sticks)を選び、続いてソースを選びます。**Left** と **Right** は、これまでどおりソースを直接切り替えます。

### Sintered

**Sintered** は、ネイティブのワンショットのデジタルパーカッションシンセです。ノートが基音のピッチを決めます。6 つのモデルは、`Knot`、`Shard`、`Burst`、`Comb`、`Logic`、`Melt` です。すべてのモデルが **Decay**、**Mod**、**Motion** を持ち、さらにモデル固有のコントロールが 3 つあります。Knot は Ratio/Spread/Fold、Shard は Ratio/Feedback/Bite、Burst は Noise/Color/Feedback、Comb は Time/Damping/Regen、Logic は Rate/Pattern/Crush、Melt は Ratio/Chaos/Drive を使います。**Mod** は常に、内部の結合の深さです。

Motion は、ピッチのグライドではなく、内部のマクロエンベロープです。`80` 未満の値は AD シェイプ、`80` はオフ、`80` を超える値はディケイのみのシェイプになります。中心から離れるほど、エンベロープは速くなります。デスティネーションはモデルごとに固定されているため、Sintered はトラッカーのパターンの中でも予測しやすいままです。Knot は Mod/Fold、Shard は Feedback/Bite、Burst は Noise/Color/Feedback、Comb は Damping/Regen、Logic は Rate/Crush、Melt は Chaos/Drive をアニメーションさせます。すべてのモデルは、ノートのトリガー時に状態をリセットし、再現性のあるヒットのために内部フィードバックを制限します。

### MME

**MME**(Multi Modulation Engine)は、オシレーター同士の相互作用に特化した 2 オシレーターのシンセです。モデルは、`Ring`、`Fold`、`Cross`、`VPM`、`Sync`、`Logic`、`Vocode` です。2 つのオシレーターはどちらも内部のもので、トラッカーのノートに従います。`Interval` が両者の関係を設定します。

6 つのマクロは、**Waves**、**Interval**、**Amount**、**Flow**、**Feedback**、**Shaper** です。Waves は、音楽的な A/B の波形ペアを選びます。Amount はモデルの中心となる相互作用を、Flow はその方向やアルゴリズムのバリエーションを制御します。Feedback は制限されていますが、範囲の終わりでは意図的に荒々しくなります。Shaper は共通の最終段で、クリーンからサチュレーション、ウェーブフォールディングへと変化します。

MME は、共有の LP/BP/HP マルチモードフィルターと ADSR を使います。6 つのマクロ、Cutoff、Resonance は、変調とモーションレコーディングで使えます。Model 上で **EDIT** を押し続けると、モデルのポップアップが開きます。

### MIDI Out

**MIDI Out**(デスクトップのみ)は、オーディオを合成する代わりに外部の MIDI 機器を制御します。ノートをトリガーすると、インストゥルメントの **Channel**(`1-16`)で本物の MIDI Note On が送られ、ノートが終わると対応する Note Off が送られます。ボリュームはベロシティになり、コードトラックの各ボイスは、それぞれ自分の Note On/Off を受け取ります。ChooChooTracker 自体からは音が出ません。先に [Settings](#12-settings) で出力デバイスを選んでください。MIDI キーボードからのサウンドプレビューを含む全体像は、[MIDI](#14-midi) を参照してください。

**Program** と **Bank high/low**(CC0/CC32)は任意で、オフのときは `--` と表示されます。`Clear` はフィールドをオフにし、その値を記憶します。設定されている場合は、そのチャンネルに最後に伝えた内容と異なるたびに、次のノートの直前に 1 回だけ送信されます(すべてのノートの前ではありません。それでは、受信側の機器のエンベロープやパッチが再トリガーされてしまいます)。

**MC1 number**-**MC4 number** は、4 つの行 FX である MC1-MC4 が、それぞれどの CC 番号(`00-7F`)に送信するかを選びます。[MIDI Out FX](#midi-out-fx) を参照してください。こちらも `--`/任意で、未設定のままのスロットは、その FX が何もしなくなります。

### サブトラクティブエンジン

このカテゴリーのエンジンは、VCO、VCF、VCA のアーキテクチャーを共有します。

利用できる VCO のタイプは次のとおりです。

- **Braids**
- **Plaits**
- **Plaits-Alt**
- **Sampler**
- **2xSCWF**
- **BYOWTBL**

各インストゥルメントは、自分の VCO をマルチモードフィルターに送ります。

フィルターは、スロープを `12 dB` と `24 dB` で切り替えられ、ローパス(LP)、バンドパス(BP)、ハイパス(HP)として動作します。

フィルターには、いくつかのキャラクターがあります。

- **Clean**: 無機質でデジタルな音
- **Classic**: 古典的なアメリカンアナログシンセに着想を得たもの
- **Aggro**: 唸りを上げる日本製アナログシンセに着想を得たもの
- **Acid**: サイケデリックに着想を得たもの

Classic、Aggro、Acid は、このアルファ版では非常に強くレゾナンスがかかることがあります。低めの値から始めて、少しずつ上げてください。

フィルターは、ADSR エンベロープで制御される VCA に信号を送ります。エンベロープの形状は、指数、リニア、対数の各カーブの間で変化させられます。

#### Plaits と Plaits-Alt

**Plaits** には 24 のエンジンがあり、選択ポップアップでは次のようにグループ分けされています。

| カテゴリー | エンジン |
|---|---|
| Analog / Waves | `00 VA VCF`, `01 PHASE DIST`, `05 WAVE TERRAIN`, `06 STRING MACH`, `08 VIRTUAL ANALOG`, `09 WAVESHAPING`, `11 FORMANT`, `12 HARMONIC`, `13 WAVETABLE`, `14 CHORD` |
| FM | `02 6-OP FM 1`, `03 6-OP FM 2`, `04 6-OP FM 3`, `10 2-OP FM` |
| Digital | `07 CHIPTUNE`, `15 SPEECH` |
| Texture / Noise | `16 SWARM`, `17 NOISE`, `18 PARTICLE` |
| Physical | `19 STRING`, `20 MODAL` |
| Drums | `21 BASS DRUM`, `22 SNARE DRUM`, `23 HI-HAT` |

**Plaits-Alt** は、元の Plaits モジュール向けの代替モデルのコレクションです。多くは、平均的な VCO よりも奇妙だったり実験的だったりします。

| カテゴリー | エンジン |
|---|---|
| Granular / Micro | `GLISSON`, `PULSAR`, `GENDY`, `SCANNED`, `LOOPBACK` |
| Phase / Harmonic | `PHASE WEAVE`, `SIDEBAND BANK`, `UNDERTOW`, `ATTRACTOR`, `LOCKSTEP` |
| Acoustic / Physical | `REED PIPE`, `BRASS`, `SHAKERS`, `CLAPS`, `FRESHETS FORMANT` |
| Polyphony / Harmony | `DIATONIC CHORD`, `SCALE STACK`, `WT DIATONIC CHORD`, `WT SCALE STACK`, `HELIX` |
| Digital / Weird | `BYTEBEAT`, `RULEFIELD`, `SPECTRAL SPIRAL`, `PHASE FLOCK` |

パラメーターは、Mutable の設計に従っています。

- **Harmonic** は、エンジン内の倍音の関係、バランス、モデルの選択を制御します。
- **Timbre** は、一般に、暗くまばらなスペクトルから、明るく密なスペクトルへと動きます。
- **Morph** は、音色のもう 1 つの次元を探ります。
- **Main/Aux** は、メイン出力とエンジンの代替出力をブレンドします。

正確な意味はエンジンによって異なります。たとえば、コードエンジンでは、コードの種類、転回形、波形に使われます。フィジカルモデルでは、素材、励起、ディケイに、ドラムエンジンでは、トーン、キャラクター、ディケイに使われます。詳細は Plaits のユーザーマニュアルを参照してください。

`CHORD`、`DIATONIC CHORD`、`WT DIATONIC CHORD` では、Harmonic に生のコントロール値ではなく、選択したコード名(`MIN`、`MAJ`、`MIN7`、`MAJ7` など)が表示されます。Braids の `WAVE PARA` も、同様に Color のボイシングに名前を付けています。

**Engine** をタップすると、カテゴリー別のエンジンリストから選べます。

**Env Mode** には 2 つのルーティングがあります。

- `TRIG` は、TRIG を接続し、LEVEL を未接続にした状態のモジュールを再現します
- `VCA` は、LEVEL を開いたままにして、ボイスのあとにトラッカーの ADSR を適用します

#### Sampler

このクリーンなサンプルエンジンは、RAM に読み込まれたモノラルまたはステレオの PCM サンプルを再生します。

- **Sample** をタップして、非圧縮の `8 ビット`、`16 ビット`、`24 ビット` の PCM WAV を読み込みます。ブラウザーで **PLAY** を押すと、ハイライトされたファイルを試聴できます。
- サンプルが読み込まれると、その名前の横に **EDIT** が表示されます。タップすると、Sample Edit 画面が開きます。**OPT** または **SELECT + [LEFT]** でインストゥルメントに戻ります。
- Sample Edit 画面には、ファイル名(RAM 上のサンプルがディスク上のファイルと異なる場合は `*` マーカー付き)、フォーマットの表示(サンプリングレート、チャンネル)、縦に大きな波形、**Region**、**Select**、**Slice**、**Process**、**File** の各フィールドが表示されます。
- 編集内容は、保存の操作で書き込まれるまで RAM にのみ存在します。プロジェクトはサンプルのファイルパスを保存し、次回のプロジェクト読み込み時にディスクから WAV を読み込み直すため、**Save**/**Save As** をせずにトラッカーを終了すると、処理操作は破棄されます(`*` マーカーが警告です)。別のサンプルをインストゥルメントに読み込んだ場合も、保存されていない編集は破棄され、Region はサンプル全体(Start `00`、End `FF`)にリセットされます。
- **Region** は、再生の Start/End マーカーを設定します。Sampler のインストゥルメント画面でも設定できます。これらは正規化された再生の境界(`00-FF`)を設定し、Start が End より後ろにある場合、サンプルは逆再生されます。**EDIT + [LEFT/RIGHT]** は、マーカーを 1(`01`)刻みで細かく調整し、**EDIT** を押している間、その周囲で波形をズームします。**EDIT + [UP/DOWN]** は大きく(ステップ 16)調整し、表示をサンプル全体に戻します。**EDIT + OPT** は、マーカーをデフォルト(Start `00`、End `FF`)にリセットします。
- 波形ビューは、編集中のマーカーの周囲の 1 秒分のオーディオの固定ウィンドウにズームし、マーカーが見えるようにパンします。ウィンドウに収まるサンプルは、フルの 1:1 表示のままです。ズームは一時的なもので、**EDIT** を押している間だけ続き、**EDIT** を離すと、大きなステップのときと同様にフルの 1:1 表示に戻ります。画面に入ると、常に表示がサンプル全体にリセットされます。
- **Select** は、再生の Start/End マーカーとは独立に、処理の選択範囲を絶対フレームで設定します。**EDIT + [LEFT/RIGHT]** は、ハンドルを 20 フレーム動かし、**EDIT** を押している間そこにズームします。**EDIT + [UP/DOWN]** は `frameCount/64`(最小 16)ずつジャンプし、サンプル全体の表示に戻ります。ハンドル上での **EDIT**(タップ)は、現在の Start または End マーカーの位置をそこにコピーします。どちらかのハンドル上での **EDIT + OPT** は、選択範囲全体を空にします。選択範囲が空のとき、両方のハンドルに `-` が表示されます。ハンドルが逆転した場合は、自動的に入れ替わります。選択範囲は、そのセッションだけのエディターの状態です。プロジェクトには保存されず、画面に入ったときに再生の Region の範囲で初期化されます(デフォルトのマーカーならサンプル全体です)。
- **Slice** は、**Mode**、**Count**、**Slice**、**Frame** の 4 つの値セルを持つ 1 行で、インストゥルメントと一緒に保存されます。Off は Start/End のウィンドウを再生します。フレーズのノートは、**C-0** から半音階でスライスを選び、最後のスライスを超えたノートは先頭に戻ります(ノート N はスライス
  `N % count` を再生するため、最後のスライスを超えて続けると、最初のスライスに戻ります)。
  スライスされたノートはピッチをトランスポーズせず、Scale のクオンタイズも使いませんが、**CRD** は
  選択したスライスを保ち、そのボイスをコードとしてトランスポーズします。スライスの開始位置は、
  波形上に 2 ピクセル幅の短い線(暗いオレンジ。現在のスライスの線は明るい)で示され、カーソル下のスライスには
  波形上に黒い背景の帯が付きます(帯の上には選択範囲の色味は描かれないため、完全な黒のまま
  プレビューの残りの部分とはっきり区別されます)。
  - **Mode** は、`OFF` / `EQUAL` / `AUTO` / `LAZY` を切り替えます(EDIT + 左/右、またはタップ。EDIT + OPT でスライスをオフにします)。モードを切り替えると、スライスのポイントが初期化されます。**EQUAL** は、Start/End のウィンドウを **Count** 個に等分します。**AUTO** は、ウィンドウに対してトランジェントの検出を実行し、見つかった各オンセットにスライスを配置します(最大 **Count** 個まで)。**LAZY** は、ウィンドウ全体を覆う 1 つのスライスから始まります。LAZY に切り替えると、現在の EQUAL/AUTO の設定(個数と境界)が保管され、EQUAL または AUTO に戻すとそのまま復元されます。確認は求められず、何も失われません。Slice と Stretch は排他的です。一方を有効にすると他方が無効になり、Stretch が長さを決めている間は、Slice のセルが暗くなります。
  - **Count** は、スライスの総数(`01`..`64`)を示します。**EDIT + [LEFT/RIGHT]** は 1 ずつ変更し(最小 1、最大 64)、**EDIT + [UP/DOWN]** は 2 の累乗の個数 `2 / 4 / 8 / 16 / 32 / 64` を、先頭へ戻りながら循環します。変更のたびに分割が再計算されます。**EQUAL** はウィンドウを再び等分し、**AUTO** は新しい目標値で検出をやり直します(検出の感度は個数から導かれ、スライスが多いほど、しきい値は敏感になります)。モードが OFF のとき、このボックスには `-` が表示されます。**LAZY** では明るいままですが(手で配置したスライスを数えます)、表示専用です。カーソルはこれを飛ばします。**Mode** から右へ、または **Slice** から左へ移動すると **Slice** に着き、**Select** 行の **END** マーカーから下へ移動した場合もそこに着き、ボックスをタップしても何も起こりません(手で配置したスライスには、再計算する分割がありません)。ここでは **EDIT + OPT** や単なる **EDIT** のタップは何もしません。スライスをオフにするのは **Mode**、スライスの削除は **Slice** で行います。
  - **Slice** はブラウザーで、1 から数える現在のスライス(`01`..count)を表示します。**EDIT + [LEFT/RIGHT]** は 1 つずつ、**EDIT + [UP/DOWN]** は 4 スライスずつ移動します(どちらも範囲内に制限され、先頭へは戻りません)。閲覧中のスライスは、波形上でより明るいマーカーと黒い帯で示され、ズームしたビューはスライスの開始位置に中心を合わせ直します。**EDIT + OPT** は、現在のスライスを削除します(直前のスライスに統合されます。最初のスライスは削除できず、最後に残った 1 つのスライスを削除すると、スライスがオフになります。境界は OFF を経由しても保持され、モードを選び直すと戻ります)。**EDIT**(タップ)は、現在選択しているスライスをワンショット再生で試聴します(どのスライスモードでも動作し、キーを離すか画面を離れると試聴が止まります)。モードが OFF のとき、このボックスには `-` が表示されます。
  - **Frame** は、現在のスライスの開始フレームを 16 進数で表示します。**EDIT + [LEFT/RIGHT]** は 10 フレームずつ動かし(**EDIT** を押している間、マーカーにズームします)、**EDIT + [UP/DOWN]** は 100 フレームずつ動かして、フルビューに戻ります。マーカーは自分のスライスの範囲内に留まり、直前または直後のスライスの開始位置を越えられません。**EDIT + OPT** は、スライスを削除します。
  - **B** は、この画面のほかの場所と同様に、Slice 行からインストゥルメント画面へ戻ります。**SHIFT + LEFT** はどこからでも抜けます。
  - **LAZY のワークフロー**: LAZY を選んだ状態で **PLAY** をタップすると、サンプル全体のワンショット再生が始まります。先頭から 1 回再生され、サンプル本来のピッチと速度で自動的に止まります(緑の 2 ピクセルのマーカーが、波形上の位置を追います)。もう一度 **PLAY** をタップすると、途中で止まります。再生中は、カーソルがどこにあっても、**EDIT** をクリックするたびに、再生位置にスライスが置かれます(既存のスライスから 50 ms 以内のスライスは、`Too close to slice` で拒否されます)。サンプルをもう一度再生すると、既存のカットが保たれ、タップした各位置に新しいカットが順に追加されます。**Count** ボックスは、スライスが置かれるたびに更新され、**Slice** ブラウザーは新しいスライスに追従します。手で配置したスライスには、ほかのモードと同じ閲覧と編集のルールが適用されます。**Slice** での **EDIT + 方向キー** で閲覧し、**Frame** で選択した開始位置を調整し、**EDIT + OPT** で現在のスライスを削除します。再生中のドロップが待機状態にある間、Frame のセルは暗くなります。**SHIFT + PLAY** は LAZY でも横取りされず、ほかの画面と同じようにフレーズの再生を始めます。LAZY のスライスは、EQUAL や AUTO とまったく同じようにシーケンサーで再生されます。フレーズのノートは **C-0** から半音階で、手で配置したスライスに割り当てられ、最後のスライスを超えると先頭に戻ります。
  - **組み合わせのヒント**: カーソルが Slice 行のセル上にあり、ほかのメッセージが表示されていないとき、ステータスバーにそのセルのヒントが表示され、カーソルがそこにある間は表示が続きます。**Mode** では、ヒントは有効なモードに紐づき、説明のみが表示されます(モード名はすでにセルに表示されています): `Divides sample in equal parts`、`Divides sample based on transients`、`Press Play and add slices with EDIT`。モードを切り替えるとテキストがすぐに入れ替わり、OFF ではバーが空になります。**Count** では `Adjust the number of slices`、**Slice** では `Browse slices`、**Frame** では `Adjust slice start` と表示されます。操作のメッセージが出ると、期限が切れるまでヒントはそのメッセージに置き換わります。
- **Process** は、破壊的な編集操作を選びます。**Crop**、**Normalize**、**Delete**、**Silence**、**Fade In**、**Fade Out**、**Reverse** です(EDIT + 左/右で循環、タップで順送り、EDIT + OPT で「なし」)。同じ行の **GO** は、選択した操作を現在の選択範囲に実行します。選択範囲が空の場合は、サンプル全体が対象です。**Crop** は選択範囲だけを残します。**Normalize** は、選択範囲のピークがフルスケールに達するようスケーリングします(ステレオイメージを保つため、両チャンネルは同じゲインを共有します)。**Delete** は、選択範囲を削除して前後をつなぎます(サンプル全体の削除は拒否されます)。**Silence** は、ゼロにします。**Fade In**/**Fade Out** は、選択範囲を無音から/無音へ直線的にランプさせます。**Reverse** は、選択範囲を逆再生にします(フレームがその場で入れ替えられ、フレームの両チャンネルは一緒に動き、長さとマーカーは変わりません)。Crop と Delete には選択範囲が必要です。選択範囲が空のときは、`Select region first` と表示されます。どの操作も、オーディオを短く一時停止し、1 段階の取り消しを保持し、サンプルを RAM 上で変更済みとしてマークします。ディスク上のファイルは、Save の操作(下記参照)まで変更されず、画面を離れると、取り消しスロットは破棄されます。
- **UNDO**(GO の隣)は、サンプルを直前の操作の前の状態に戻します。操作が実行されるまでは暗くなっており、繰り返し押すと、操作前と操作後の状態の間を切り替え、画面に入り直すと消去されます。
- **File** には、保存の操作があります。インストゥルメントは、読み込み元の WAV の完全なパスを保存します。これらの操作は、そのファイルを書き込むか、インストゥルメントを新しいファイルに向けます。インストゥルメント名には一切触れません。
  - File フィールドは、**Save** と **Save As** を切り替えます(EDIT + 左/右、またはタップ)。同じ行の **GO** は、表示されている操作を実行します。
  - **Save** は、サンプルの読み込み元の WAV を上書きします。スライスのないサンプルでは、まず `Overwrite <name>?` と確認されます。スライスされたサンプルでは、まず **SAVE SLICES** ダイアログが開き、スライスのポイントをどこに属させるかを尋ねます。**SAVE TO SAMPLE** は、cue チャンクとして WAV に書き込み(持ち運び可能で、DAW ではマーカーとして表示されます)、プロジェクトにも保持します。**SAVE TO PROJECT** は、通常の WAV を書き込み、ポイントはプロジェクトにのみ保持します。**CANCEL** は中止します。`Don't ask again in this project` チェックボックスは、選んだ保存先をプロジェクトとともに保存し、以降はダイアログを省略します(この選択は .cct に `- Sample save choice:` として保存され、プロジェクトファイルを編集しない限り変更できません)。スライスのないサンプルでは、ダイアログは省略されます。ファイルパスを持つサンプルが読み込まれるまで、**Save** は暗くなり、ナビゲーションでも飛ばされます。書き込みに失敗した場合は、変更済みマーカーが残り、エラーが表示されます。
  - **Save As** は、現在のサンプルを新しいファイルに書き込みます。ファイル名を入力し(現在の名前から拡張子を除いたものが入力済みです)、続いてブラウザーでフォルダーを選びます。サンプルは `<folder>/<name>.wav` として書き込まれ、インストゥルメントは新しいファイルを指し、そのフォルダーがデフォルトのサンプルフォルダーとして記憶されます。サンプルデータが読み込まれるまで、これは暗くなり、ナビゲーションでも飛ばされます。そのため、読み込んだばかりのサンプルにも、ファイルパスを与えられます。255 文字を超えるパスは拒否されます。
  - ファイル名の前の `*` マーカーは、RAM 上のサンプルがディスク上のファイルと異なることを意味します(処理操作のたびに付き、Save と Save As で消えます)。このマーカーはセッション限りのもので、プロジェクトには保存されず、画面に入り直すとリセットされます。複数のインストゥルメントが同じ WAV ファイルを参照している場合、1 つを保存すると、すべてのインストゥルメントにとってそのファイルが上書きされます。
- Sample インストゥルメント画面では、**EDIT + [LEFT/RIGHT]** で、同じフォルダー内の前または次の WAV を読み込めます。
- **Pitch** は、半音単位でトランスポーズします(`-48` から `+48`)。
- **Loop** は、Off、Loop、Ping-Pong を選びます。
- **Speed** は、`0%` から `500%` までのグラニュラーなタイムストレッチを制御します(`100%` が通常です)。

サポートされていない WAV フォーマットは、エラーを表示します。普通でないファイルは、インポートする前に `PCM8`、`PCM16`、`PCM24` の WAV に変換してください。

#### 2xSCWF

2xSCWF は、ツインのシングルサイクル波形オシレーターです。各オシレーターに、ちょうど 1 周期を含むモノラルの WAV を 1 つずつ読み込みます。どちらのオシレーターも前向きに読み、サイクルの終わりで折り返します。

Mix は、A と B をクロスフェードします。

Detune は、ユニゾンから `+200 ct` までは細かく指数的で、それを超えると `+3 st` から `+24 st` まで半音ステップで動きます。

2xSCWF は、各ファイルを 1 サイクルのテーブルとして扱い、オシレーターの 1 サイクルにつきちょうど 1 回読みます。これにより、2 つのシングルサイクル波形をブレンドしたりデチューンしたりできます。

工場出荷の `waveforms/AKWF/` フォルダーには、Adventure Kid ライブラリーの波形が入っています。コレクションを広げたい場合は、オンラインにもっと多くあります。

#### BYOWTBL

BYOWTBL は、Serum のテーブルと互換性のあるデュアルウェーブテーブルオシレーターです。各オシレーターは、連続したシングルサイクルのフレームを含むモノラルの WAV を読み込みます。`Pos A` と `Pos B` は、それぞれのテーブルを `00` から `FF` まで独立にスキャンします。エンジンは、各フレームの内部と隣り合うフレーム間を、線形に補間します。`Mix` はオシレーターをクロスフェードし、`Detune` はオシレーター B をオフセットします。

## 6. モジュレーションとモーションレコーディング

各インストゥルメントは、最大 4 つのモジュレーションスロットを持てます。オーディオインストゥルメントは、**Instrument Pan** または **Track Pan** をターゲットにできます。どちらも、`00` が左、`80` が中央、`FF` が右です。

利用できるモジュレーションのタイプは次のとおりです。

- ADSR - 古典的なアタック、ディケイ、サスティン、リリースのエンベロープ
- AHD - アタック、ホールド、ディケイのエンベロープ
- LFO - 複数の波形を持つ低周波オシレーター
- SLFO - 遅いサイクル用に、周期の倍率を持つ LFO
- FLFO - kHz の範囲まで届く、オーディオレートの LFO。FLFO は CPU への負荷が大きくなることがあります
- SLIN - リニアなジョイスティック制御
- SRAT - レートベースのジョイスティック制御

モジュレーションのデスティネーションのリストは、インストゥルメントのタイプによって異なります。

`Cutoff` のデスティネーションでは、Amount は 2 次の応答を持つ指数的なものになります。25% で 4.5 半音、50% で 18 半音、75% で 40.5 半音、100% で 6 オクターブに達します。これにより、小さな量では細かい制御を保ちつつ、深いスイープも可能です。

ADSR または AHD のエンベロープが Volume をターゲットにしている場合、それがインストゥルメントのボリュームエンベロープになります。Volume をターゲットにした LFO は、代わりに現在の出力ボリュームをオフセットします。

モジュレーションの量は、正にも負にもできます。その範囲は、デスティネーションによって異なります。デスティネーションの全範囲が `127` 以下の場合(ほとんどのパラメーターがそうです)、量は絶対的な範囲を定義します。ピッチのような、より広いデスティネーションでは、スケーリングされた量が使われます。

アタック、ホールド、ディケイ、周期など、すべての長さのパラメーターは、ティックで測られます。

LFO の波形:

- Tri - 双極性の三角波
- Sin - 双極性の正弦波
- UniTri - 単極性の三角波
- UniSin - 単極性の正弦波
- RampDn - 直線的に下がるランプ(ノコギリ波)
- RampUp - 直線的に上がるランプ(ノコギリ波)
- ExpDn - 指数的に下がるランプ(指数的ノコギリ波)
- ExpUp - 指数的に上がるランプ(指数的ノコギリ波)
- Square - 矩形波
- Random - サンプル&ホールドのランダム波
- Wavetable - プロジェクトの 32 ステップの AY ウェーブテーブルの 1 つを読み取ります。`00` から `0F` の値は、補間なしで `-100%` から `+100%` に対応します。

LFO のトリガータイプ:

- Free - インストゥルメントが変わったときだけ LFO を再スタートします
- Retrig - ノートごとに LFO を再スタートします
- Phrase - 再生が新しいフレーズに入ったときに、LFO と SLFO を再スタートします
- Chain - 再生が新しいチェーンに入ったときに、LFO と SLFO を再スタートします
- Hold - 1 サイクルのあとに止まり、最後の値を保持します
- Once - 1 サイクルのあとに止まり、ゼロに戻ります

### モーションレコーディング (Motion recording)

- **STICK LIVE**(デフォルトは `L1`)は、フレーズを変更せずに、スティックによる変調を適用します。**Settings > Stick live mode** で、`HOLD`(デフォルト)は押している間だけ有効にし、`TOGGLE` は 1 回押すと有効に、次に押すと無効にし、`FREE` は常に有効のままにします。`TOGGLE` でボタンを離しても、有効のままです。
- 再生中に **MOTION RECORD**(`L2`)を押し続けると、スティックによる変調が適用され、変更されたデスティネーションが、絶対的な FX の値として記録されます。
- **MOTION ERASE**(`R2`)を押し続けると、現在の行から、対応するデスティネーションの FX が削除されます。

右下の `~` は、Stick live が有効であることを示します。Record(`*`、オーバーフロー時は `!`)と Erase(`x`)は、インジケーターの優先度が高く、どちらのモードでも一時的なままです。どちらも、押している間はスティックのライブ処理を有効にし、離しても、別途有効にしたライブのトグルはそのまま残ります。

モードはアプリの設定とともに保存されますが、ライブのトグルは、起動時には常にオフです。モードを変更すると、トグルは解除されます。`HOLD` は、現在押されている Stick live ボタンに従い、`TOGGLE` は新たな押下を待ち、`FREE` は即座に有効になります。

モーションレコーディングは、現在再生中のフレーズに、トラック FX を書き込みます。まず、対応する FX を更新し、次に、右から左へ空いているスロットを使います。異なる FX を上書きすることはありません。3 つのスロットがすべて埋まっている場合、そのモーションは、そのステップには記録されません。右下の `!` は、3 つの FX 列に収まる数より多くのデスティネーションが変化したことを意味します。

モーションレコーディングは、Braids、Plaits、Sampler、2xSCWF、BYOWTBL、Bogie のデスティネーションに対応しており、該当する場合は、アクティブな Bogie のマクロとフィルターのコントロールも含みます。

## 7. Tables

テーブルは、トラッカーにおける中心的なサウンドデザインのツールです。Vortex Tracker の用語では、インストゥルメントとオーナメントを組み合わせたものですが、それ以上のことができます。LSDj や NerdSEQ を知っているなら、考え方はすでに馴染みがあるはずです。

Pitch 列は、半音単位の相対(`~`)または絶対(`=`)のピッチ値を受け付けます。Volume 列は `00`-`0F` で、すべてのエンジンでエンベロープの上に適用され、ゲートとして使えます。`0F` と `00` を交互に置いて、`HOP 00` でループさせます。4 つの FX レーンは、ほぼフレーズのレーンと同じですが、いくつかの FX は、テーブルでは異なる動作をします。

テーブルの最終行に `TIC` FX を置くと、その列の速度が設定され、インストゥルメントのデフォルトのテーブル速度を上書きします。各 FX 列は、異なるティック速度で動作できます。Pitch 列と Volume 列は、1 番目の FX 列の速度に従います。

16 行のテーブルは、長い Vortex Tracker のインストゥルメントと比べて短く見えるかもしれませんが、`HOP` FX によって、「この行を 5 回繰り返す」のような条件付きのループや、入れ子のループを作れます。ループと独立した FX 列の速度を組み合わせれば、この 16 行は驚くほど遠くまで届きます。

### Retrigger モード

Table 画面の上部の `Retrig` フィールドは、すでにアクティブなテーブルがいつ再スタートするかを選びます。`Inst` はデフォルトで互換性のあるモードです。インストゥルメントを含むフレーズの行は、そのインストゥルメントのデフォルトのテーブルを選び、行 `00` から開始します。`Phrase` は、再生がフレーズに入ったときに、アクティブなテーブルを再スタートし、`Chain` はチェーンに入ったときに再スタートし、`Free` は、トラックが止まるか、明示的なコマンドが置き換えるまで、動作し続けます。

構造的なモードは、時間をさかのぼることはありません。トラックにアクティブなインストゥルメントのテーブルがない場合、インストゥルメントを最初に導入するフレーズの行が、フレーズの行 `4`、`8`、`F` であっても、まさにその行で、そのテーブルを有効にします。あとのインストゥルメント番号は、アクティブな `Phrase`、`Chain`、`Free` のテーブルを置き換えません。これにより、以前のフレーズのステップを黙ってシミュレートすることなく、テーブルを LFO のようなオートメーションとして使えます。

`TBL`、`TBX`、`RET` は、常に明示的な動作です。モードにかかわらず、即座に選択または再スタートします。Phrase や Chain の境界では、その再スタートが新しいフレーズの行が読まれる前に行われるため、その行の `TBL` や `TBX` が最終的な決定権を持ちます。そのため、テーブルの行 `00` の FX は、通常どおり再び実行されます。累積型の FX は、通常の累積を保ちます。

テーブル `00-7F` は、デフォルトのインストゥルメントテーブル用に予約されています。テーブル `80-FE` は、`TBX` エフェクトで開始される補助テーブル用です。下位の範囲も補助テーブルとして使えますが、そのように使うと、予期せぬ競合や混乱を招くことがあります。

### Phrase と Table の間での FX のコピー

FX の名前/値の列だけを選択し、Phrase からコピーまたは切り取って、Table の任意の FX レーンに貼り付けます。その逆も可能です。コピーは、選択したセルをそのまま保つため、コマンドのみ、または値のみの選択は、部分的なままです。貼り付けは、現在の FX セルから始まり、行 `F` と、貼り付け先の最後の FX レーンで切り捨てられます。ノート、インストゥルメント番号、ピッチ、ボリュームは、この 2 つの画面の間では移動しません。

### 操作

- FX 名の列での **EDIT + [UP/DOWN]**: FX 選択画面を開く
- **OPT + [DIRECTION]**: テーブル間を移動

## 8. その他の画面

### Instrument Pool

Instrument Pool は、プロジェクト内のすべてのインストゥルメントを表示し、並べ替えられます。再生中は、現在アクティブなインストゥルメントも表示されます。

#### 操作

- **EDIT**: インストゥルメントを編集し、Instrument 画面へジャンプ
- **SHIFT + OPT**: インストゥルメントをコピー
- **SHIFT + EDIT**: インストゥルメントを貼り付け
- **EDIT + [UP/DOWN]**: インストゥルメントを並べ替え
- **EDIT + PLAY**: インストゥルメントを試聴

### AY Wavetable

Wavetable は、AY Plus のソフトウェアオシレーターのタイプです。1 つのプロジェクトには、それぞれ 32 ステップのウェーブテーブルを最大 256 個含められます。すべてのウェーブテーブルインストゥルメントは、同じ波のセットを共有します。この画面で、それらを編集します。

AY のボリュームレベルは非線形なので、Standard ビューの波形は、実際の出力レベルに合うように描かれます。**OPT** を 2 回タップすると、Standard ビューと、保持される **LFO ビュー** が切り替わります。これは Song/Live Mode と同じショートカットです。LFO ビューは、`0` から `15` の生のステップを線形に描き、`7` と `8` の間の中心線が、モジュレーションのゼロ点です。

この画面には、2 つの論理的な行があります。上の行には **Load** と **Save** のボタンがあり、2 行目には、ウェーブテーブルエディターがあります。

#### 操作

- **OPT + [LEFT/RIGHT]**: ウェーブテーブルのリストを移動
- **OPT + [UP/DOWN]**: リストを 16 波ずつ移動

- **OPT + PLAY**: Standard ビューと LFO ビューを切り替え

## 9. Tracker FX

トラック FX は、個々のステップで、シーケンサーやサウンドエンジンの値を強制的に設定します。ほかのグルーヴボックスでは、これを「パラメーターロック」と呼ぶことがよくあります。Phrase の各行には 3 つの FX スロットがあります。

各 FX は、3 文字のコマンドと 16 進数の値を持ちます。アプリ内のヘルプパネルには、選択したコマンドの短い説明が表示されます。

### スケールのオートメーション (Scale)

`SCL XY` は、フレーズに保存されたノートを変更せずに、グローバルな再生スケールとルート音を変更します。`X` はスケール(`0` Chromatic、`1` Major、`2` Minor、`C` Custom まで)を、`Y` はルート音(`0` C から `B` B)を選びます。このコマンドは、フレーズの FX にのみ適用され、テーブルには適用されません。複数のトラックが同じティックで `SCL` を発行した場合は、最も小さい番号のトラックが優先されます。

`SCL` は Quantizer モードに属します。**Note Lock** がオンのときは、コマンドは FX リストに表示されず、すでにフレーズに書き込まれている `SCL` は、そのモードがオンの間は無視されます。

### コード (Chords)

`CRD XY` は、自分と同じ Phrase の行にあるノートを、コードに変えます。`Y` は、`0` Major、`1` Minor、`2` Dim、`3` Aug、`4` Sus2、`5` Sus4、`6` Power、`7` Maj7、`8` Min7、`9` Dom7、`A` Min7b5、`B` Dim7、`C` Add9、`D` MinAdd9、`E` Maj9、`F` Min9 から選びます。`X` は 16 種類のボイシングのうち 1 つを選びます。`0-3` は上昇する密集転回形のサイクルで、`4-7` は drop-2 を加え、`8-B` は drop-3 を加え、`C-F` は両方の drop を組み合わせます。サイクルは、三和音とパワーコードでは、さらに 1 オクターブ分続くため、すべての値が異なります。値が大きいほど、段階的に広く、より型破りになります。たとえば、`CRD 4Y` は drop-2 の基本形、`CRD DY` は両方の drop を使った第 1 転回形です。ピッチテーブルの下端または上端では、ボイスがその範囲に制限されます。このコマンドは持続しません。コードにする行ごとに書いてください。生成された各ノートは、Scale が有効なとき、Quantizer と Note Lock の両モードで、個別にクオンタイズされます。ソフトウェアエンジンでのみ利用でき、AY インストゥルメントは無視し、モノフォニックのままです。

#### 条件

スウェーデン式の「trig conditions」に着想を得て、トラッカーは、トリガー確率とモジュロ条件に対応しています。

| FX | 値 | 意味 |
|---|---|---|
| `PRO` | `00-64` | `0%` から `100%` の絶対的なトリガー確率 |
| `MOD` | `AB` | `B` のうち `A` 回目の反復でトリガー。例: `12`、`22`、`14`、`34` |

`MOD` のカウンターは、トラックとフレーズに固有です。`A` が `B` より大きいなどの無効な組み合わせは、トリガーされません。

`MOD34` は、4 パスのサイクルの 3 回目のパスでトリガーされます。`MOD1F` は、16 パスのサイクルの 1 回目のパスでトリガーされます。

#### 再生速度

NerdSEQ と同様に、ChooChooTracker は、トラックごとに独立した再生速度に対応しています。

`SPD` は、その値を符号付きバイトとして読みます。`00` は通常の速度で、正の値はトラックを速く、負の値は遅くします。設定は、別の `SPD` コマンドで変更されるまで有効です。

| 値 | 速度 |
|---|---:|
| `00` | `x1` |
| `01` | `x2` |
| `02` | `x3` |
| `7F` | `x128` |
| `FF` | `/2` |
| `FE` | `/3` |
| `80` | `/129` |

符号付きの `SPD` に対応していない古いプロジェクトは、元の `00-10` の対応を保つため、保存されたとおりに再生されます。

非常に大きな倍率は、トラッカーのティックスケジューラーの分解能を超えることがあり、実機では検証されていません。

## 10. Mixer、Reverb、Delay

Mixer は、一番左にあるメイン画面です。CPU の負荷とクリッピングの警告を表示します。**CLIP** 列の赤い `!` は、ドライ信号によってミックスが安全な範囲を超えたトラックを示します。

これを使って、8 つのトラックのバランスを取り、各トラックを Tilt EQ で整え、リバーブやディレイにオーディオを送ります。

| フィールド | 意味 |
|---|---|
| LVL | エンジン後のトラックレベル、`000-100` |
| REV | 共有の Clouds リバーブへのセンド、`000-100` |
| DLY | 共有のピンポンディレイへのセンド、`000-100` |
| TLT | トラックごとの Tilt EQ、`00-FF`。`80` がニュートラルで、低い値は低音寄り、高い値は高音寄りになります。低い値では、ソフトなオーバードライブがかかります。 |
| M | `*` でこのトラックをミュートします |
| S | `*` でこのトラックをソロにします |

ミキサーは、インストゥルメント単位ではなく、トラック単位です。トラックのインストゥルメントが変わっても、そのレベル、PAN、Tilt、センドは、トラックに結び付いたままです。インストゥルメントにも、Instrument 画面の最上段に、`00-FF` の独自の **Vol** と **Pan** があります。インストゥルメントの PAN が最初に適用され、そのあとトラックの PAN が適用されます。どちらも、中央では既存のステレオイメージを保ちます。左右へ動かすと、反対側を徐々に減衰させます。

### Master FX

**MASTER FX** のエントリーを開くと、ミックス全体用の 2 スロットの Insert FX サブメニューが開きます。そのエフェクトは、リバーブとディレイのリターンのあと、マスターボリュームの前で動作します。モジュールを選び、そのパラメーターを編集したり、トラックのインサートとまったく同じようにバイパスしたりできます。**OPT** を押すと、Mixer に戻ります。Master FX の設定は、プロジェクトとともに保存され、フレーズ、テーブル、モジュレーションによるオートメーションはされません。

### Clouds Reverb

Mixer から **SELECT + [UP]** を押すと、リバーブの設定画面が開きます。

- **Return**: マスターミックスでの、ウェットなリバーブのレベル。
- **Time**: ディケイ/時間のコントロール、`00-FF`。
- **Damping**: 高域の吸収、`00-FF`。
- **Filter**: リバーブの前に適用されるローパスフィルター。

これは Clouds のリバーブセクションであり、Clouds のグラニュラープロセッサー全体ではありません。

### Ping-pong Delay

Mixer から **SELECT + [DOWN]** を押すと Delay が開き、**SELECT + [UP]** で戻ります。Reverb は逆方向に動作します。**SELECT + [UP]** で開き、**SELECT + [DOWN]** で Mixer に戻ります。

- **Return**: ウェットなディレイのレベル。
- **To Reverb**: ウェットなディレイ信号のうち、共有のリバーブに送られる量、`0-100%`。
- **Ticks**: トラッカーのティック単位のディレイタイム(デフォルトでは `9 ticks` = `1 拍`)。
- **Feedback**: クロスフィードバックの量。`95%` に制限されます。
- **Filter**: ディレイ信号の経路にあるローパスフィルター。

最初の繰り返しは、ステレオ入力に従います。それ以降のフィードバックは、左右のチャンネルの間で交差します。

## 11. Project 画面

Project 画面には、**Load**、**Save**、**New**、**Export**、**Manage**、**Scale** の各コマンドと、ファイル名、タイトル、作者のメタデータがあります。

### エクスポート先 (Export location)

エクスポート、ステム、バウンスは、アプリの既存のサンプルディレクトリ内の、プロジェクトごとのフォルダーに書き込まれます。

- **デフォルト**: `<app folder>/samples/Exports/<project name>/`。プロジェクトに名前がない間は、フォルダーは `current-project` です。
- Web 版では、デフォルトは `/user/samples/Exports/<project name>/` です。
- Android では、サンプルフォルダーは、アプリのプライベートなワークスペースの中にあります。

EXPORT 画面の **Folder** 行には、有効な保存先が表示されます。

- **EDIT** をタップすると、フォルダーブラウザーでカスタムフォルダーを選べます。選んだフォルダーは、選んだとおりに使われ(プロジェクトのサブフォルダーは追加されません)、設定に記憶されます。
- **EDIT + OPT**(clear)で、デフォルトの場所に戻ります。

名前付きのプロジェクトが新しい名前で保存されると、デフォルトのエクスポートフォルダーは、それに合わせて名前が変更され、すでにエクスポートしたファイルがプロジェクトとともに保たれます。カスタムフォルダーには、名前の変更は適用されず、オートセーブでフォルダー名が変わることもありません。保存先の名前のフォルダーがすでに存在する場合は、両方のフォルダーが保持されます。トラッカーがフォルダーを見失った場合(たとえば再起動後)は、名前付きのプロジェクトを保存すると、代わりに既存の `current-project` フォルダーの名前が変更されます。名前の変更後もインストゥルメントは動作し続けます。名前が変更されたフォルダーを指す、読み込み済みのサンプルのパスは、自動的に更新されます。

**Load** は、`.mid`/`.midi` ファイルも受け付け、新しいプロジェクトとしてインポートします。ノートは MIDI チャンネルごとにグループ化され(トラック 1 つにつきチャンネル 1 つ、トラック数まで)、1 拍あたり 4 行にクオンタイズされ、デフォルトの AY インストゥルメント 1 つに配置されます。MIDI のプログラム番号には、チップチューンでの対応物がないため、そのあとで本物のインストゥルメントを選んでください。使われるのはファイルの最初のテンポだけです(グローバルなティックレート 1 つのみで、セクションごとのテンポ変更はありません)。Export 画面の **MIDI** 行は、その逆を行います。現在のアレンジメントのノート、ボリューム、テンポ/グルーヴを、スタンダード MIDI ファイル(トラッカーのトラック 1 つにつき MIDI トラック 1 つ)として書き出します。[MIDI Out](#midi-out) のインストゥルメントと、ボリュームとグローバルなグルーヴを超えるその他の行ごとの FX には、MIDI での対応物がなく、変換されません。

**Load** は、Dirtywave M8 のソング(`.m8s`、ファームウェア 2.x-4.x)も受け付け、新しいプロジェクトとしてインポートします。構造とノート(ソングの行、トランスポーズ付きのチェーン、ノート、ベロシティ、インストゥルメント番号を持つフレーズ、ノートオフ、テンポ、ソング名)だけが取り込まれます。ノートは実際のピッチを保ちます(M8 はオクターブを 2 つ高く表記します。M8 の `C-6` は、ここでは `C-4` です)。フレーズで使われる各インストゥルメントは、M8 のインストゥルメント名でインポートされます。M8 の **MACROSYN** インストゥルメントは、Braids インストゥルメントになります(47 種類のシェイプは Braids のモデルで、番号も同じです。timbre、color、フィルタータイプ、カットオフ、レゾナンス、パンは引き継がれますが、カットオフのカーブは近似です)。**SAMPLER** インストゥルメントは、Sample インストゥルメントになります。`.m8s` には、M8 のカード上の WAV のパスしか保存されていないため、ファイルは `.m8s` のあるフォルダーとその親フォルダー(カードのレイアウトのコピーでも構いません)、および現在のサンプルフォルダー(`Samples` と `samples` のどちらでも動作します)から探されます。見つからない場合、インストゥルメントは M8 のパスを保ったまま、無音のままになります。M8 は、サンプルを元のピッチで、このアプリより 2 オクターブ低く再生するため、インポートされたサンプルの Pitch 設定には +24 半音が加えられます。**FMSYNTH** は Genesis FM インストゥルメント(大まかな近似)に、**WAVSYNTH** と **HYPERSYNTH** は aChChid になります。**MIDI OUT** は、MIDI Out インストゥルメント(チャンネル、バンク、プログラム、最初の 4 つの CC 番号)になります。その他の(外部の)タイプは、デフォルトの AY インストゥルメントになります。そのあとで本物の音を選んでください。FX とテーブルは無視されます。

デスクトップでは、Export 画面の **M8S** 行が、限定的にその逆を行います。この行をタップして、既存の `.m8s` を**テンプレート**として選びます(終了するまで記憶され、**EDIT + OPT** で忘れます)。そのソング、チェーン、フレーズ、テンポ、タイトルは置き換えられ、それ以外はそのまま保たれます。ただし、Braids インストゥルメントは MacroSynth として、Sample インストゥルメントは Sampler として書き戻され(パスは `/Samples/<file name>`。そこに WAV を自分でコピーしてください)、テンプレートに、残りのパラメーターをコピーできるそのタイプのインストゥルメントがあることが条件です。FX はエクスポートされず、フレーズ `FF` 以上を使うソングはエクスポートできません(M8 のフレーズは 255 個です)。エクスポートしたファイルは、まだ実際の M8 では試していません。詳細は [M8 songs](../m8s-format.md) を参照してください。

デスクトップでは、key jazz により、画面上の仮想キーボードを使わずに、ファイル名、タイトル、作者をキーボードから直接入力できます。[Key jazz](#key-jazz-デスクトップのみ) を参照してください。

### Scale / Quantize

Scale 画面は、グローバルな 12-TET のスケールエンジンを制御します。**Mode** 行で、2 つのモードから選びます。

- **Quantizer**(デフォルト): フレーズの入力は半音階のままです。有効にすると、ノートはサウンドエンジンに届く直前に切り捨てで丸められるため、ルート音やスケールを変えると、フレーズを編集せずにソングが再ハーモナイズされます。
- **Note Lock**: フレーズに入力したノートは、入力時にスケールの最も近いノートにスナップされるため、スケールのノートしか書き込めません。新規の入力と減少は下にスナップされ、`EDIT + RIGHT` / `EDIT + UP` は、ノートを上の次のスケールのノートに上げます。この画面では、入力は常にプロジェクトのスケールに従います。ルート音やスケールを変えると、有効なトラックで新しく入力したノートにすぐに影響しますが、すでに保存されているノートはそのままです。このモードでは `SCL` FX は使えず、すでに書き込まれている `SCL` は無視されます。単純なノートの再生時のクオンタイズは迂回されます(入力がすでにロックされているため)。`CRD` によるコードのクオンタイズは、引き続き適用されます。

カーソルが **Mode** にあるとき、ステータスバーには、有効なモードの固定の説明が表示され続けます。**Quantizer** では `Quantizes notes on playback`、**Note Lock** では `Snaps sequencer to scale` です。モードを切り替えると、テキストがすぐに入れ替わります。操作のメッセージが出ると、期限が切れるまで、それに置き換わります。

どちらのモードも、同じルート音、スケール、**Custom** のノート編集、トラックのチェックボックスを共有します。8 つのトラックのチェックボックスは、それぞれ、どのトラックにモードを適用するかを決めます。スケールエンジンは、12 ノートでないピッチテーブルと、**Slice** モードが EQUAL、AUTO、LAZY の Sampler インストゥルメント(そのノートは C-0 から半音階でスライスを選びます)では迂回されます。MIDI 入力は、このバージョンには含まれません。

- **Linear pitch** は、ピッチテーブルのモードを選びます。**Off** はデフォルトで、AY、Braids、Plaits のオクターブトラッキングを正しく保つために、ハードウェアで検証された設定です。
- **Tick rate** は、トラッカーのタイミングを設定し、対応する BPM を表示します(`tick rate x 60 / 24`)。
- ChooChooTracker は、プロジェクトを `.cct` として保存します。この形式は ChipNomad と互換性がありません。

インストゥルメントのタイプを変更したり、別のプロジェクトを読み込んだりする前に、**Save** を使ってください。

## 12. Settings

- **Repeat delay / speed** は、ボタンを押し続けたときのリピートを調整します。
- **Stick live mode** は、すでに割り当てられている Stick live ボタンに対して、`HOLD`、`TOGGLE`、`FREE` を選びます。
- **MIDI** は、[MIDI](#14-midi) のサブメニューを開きます。デバイスの選択と、MIDI In のチャンネルとインストゥルメントの対応付けです。
- **Synths** には、**AY Quality**、**Sample dithering**、グローバルな **Braids BITS / DRFT / SIGN** の設定が含まれます。
- **Mixer** には、**Mix volume** と、Mixer のすべての Tilt コントロールが使う、プロジェクトごとの `250-4000 Hz` の **Tilt pivot**(デフォルトは `1 kHz`)が含まれます。
- **Graphics** には、**Edit color theme**、**Load font**、**Persistent waveform**、**Track visuals**、**Waveform FPS**、有効なレンダラー(`GPU` または `Software`)が含まれます。**Waveform FPS** は、インストゥルメントのスコープとミキサーのビジュアライザーの更新レートを、`01` から `60` で設定します。Track visuals は、**Detailed**(シンセの波形とそのオーバーレイ)または **Audio waveform**(そのトラックの実際の合算出力)を、トラックごとに独立して選びます。オーディオ波形では、再生が始まると、以前の ADSR のオーバーレイがすぐに消えます。ChipNomad のフォントとテーマは動作するはずです。
- **Key mapping** は、操作をカスタマイズします。
- **Support report** は、アプリのバージョン、プラットフォーム、オーディオ設定と CPU 負荷、再生/オーバーフローの状態、プロジェクトのコンパクトな要約を含む、小さな診断用のテキストファイルを書き出します。サンプルのデータや、プロジェクトのタイトル/作者のテキストは含まれません。Android と Web では、通常のエクスポート/ダウンロードのフローが開きます。デスクトップと携帯機のビルドは、アプリの書き込み可能なフォルダーに `support-report.txt` を保存します。
- **Quit ChooChooTracker** は、正常に終了します。

**Graphics → Boot screen** は、**Original**(デフォルト)または **Night** を選びます。EDIT をタップするか、EDIT + 方向キーで変更します。選択は、次のタイトル画面のために保存されます。Night は、元の鉄道の情景を、より柔らかい青灰色のトーン、さりげない星のまたたき、ときどき現れる流れ星を伴う、手続き的な天の川とともに使います。元の風景と列車は、スクロールのループを保ちます。

## 13. パフォーマンスとトラブルシューティング

### CPU

CPU のコストは、有効なエンジンとエフェクトによって異なります。Plaits のフィジカルモデルと Clouds Reverb は、基本的な AY のボイスより重くなります。特に、8 つの Plaits ボイスと両方のセンドが有効なときは、対象の本体でパフォーマンスを確認してください。CPU の表示が `100%` に近いと、プチプチというノイズや、オーディオの締め切りの未達が起きることがあります。

CPU の表示は、オーディオのレンダリング時間を平滑化した測定値です。オーディオコールバックが実行される前や、デバイスのオーディオ出力での遅延は測定しないため、表示が低くても、ノイズが発生することがあります。

Android では、Pixel 7a の OpenSL ES で観測された断続的なノイズを避けるため、オーディオ出力は AAudio を優先するようになりました。このバッファー付きの出力は、安定した再生を優先し、反応にいくらかの遅延を加えることがあります。トラッカーのキャンバスは、正方形やその他の特殊な画面比率でも、4:3 の完全なレイアウトを保ちます。未使用の領域は、列を切り取る代わりに、枠として表示されます。ノイズが続く場合は、ソング、携帯電話のモデル、Android のバージョン、スピーカー、ヘッドホン、Bluetooth のどれを使っているかを報告してください。

プチプチ音、クラッシュ、動作の遅さに遭遇した場合は、**Settings > Support report** を使い、生成された `support-report.txt` をバグ報告に添付してください。特定のソングが問題を引き起こす場合は、その `.cct` も添付してください。

### 音が出ない

インストゥルメントの番号、トラックのミュートまたはソロの状態、トラックの LVL、アプリの Mix volume、インストゥルメントのエンベロープを確認してください。サンプルについては、元の WAV が保存されたパスにまだ存在するか確認してください。ArkOS では、**MENU + L3** を押すと、OS のミュートが切り替わります。それでも解決しない場合は、ハードウェアを再起動し、オーディオインターフェースを接続し直してください。

### 操作の感触がおかしい

Settings で Repeat delay と Repeat speed を調整してください。1 回押しただけで 2 回動く場合は、その方向に割り当てられている物理コントロールが 1 つだけであることを確認し、正確な画面とショートカットを報告してください。

## 14. MIDI

デスクトップと PortMaster 向けです。Settings > **MIDI** がこのサブメニューを開きます。**MIDI In** / **MIDI Out** は、接続されたデバイスを選びます。検出されたポートを、両端に `OFF` を置いて順に切り替えます。どちらの方向も、デバイスの選択が必要です。デバイスの選択はセッション単位で、settings.txt には保存されません。ポートのリスト内の位置は、再起動やデバイスを差す順序の違いによって変わることがあるためです。アプリの **PLAY** コントロールは、この画面でも使え、ソングを開始します。PortMaster では、起動前に USB MIDI デバイスを接続してください。携帯機の OS が ALSA を通じて公開している必要があります。

- **MIDI キーボードからのサウンドプレビュー**: MIDI In デバイスを選んでいるとき、接続したキーボードでノートを弾くと、どの画面でもインストゥルメントを試聴できます。これは、[Instrument](#5-instruments) 画面での、画面上の **EDIT + PLAY** のショートカットと同じです。プレビューのみで、ソングにノートが入力されることはありません。
- **Channel mapping**: 16 の MIDI チャンネルのリストを開きます。各チャンネルにインストゥルメントを割り当てる(デフォルトは `OFF`)と、そのチャンネルで受信したノートは、Instrument 画面でどれが選ばれていても、そのインストゥルメントを試聴します。たとえば、チャンネル `01` -> インストゥルメント `05` です。`OFF` のままのチャンネルは、現在選択中のインストゥルメントにフォールバックします。これが元の動作です。この対応付けは、settings.txt に保存されます。
- **MIDI CC mapping**: 入力されたコントローラーを、インストゥルメントのパラメーター(その **Volume** を含む)、またはグローバルなコントロールに割り当てます。グローバルな行は、インストゥルメントの代わりに `TRK 1`-`TRK 8` を表示し、トラックごとの **Mute**、**Solo**、**Volume**、**Reverb send**、**Delay send** を提供します。**Song play/stop** にはターゲットがありません。新しい割り当ては、それを学習または設定した CC を無視し、次の物理的な動きから有効になるため、再生中に割り当てを設定しても、パッチがゼロにリセットされることはありません。Mute と solo は、`0-63` = off、`64-127` = on を使います。
- **外部の MIDI デバイスの制御**: トラックに [MIDI Out](#midi-out) のインストゥルメントタイプを指定し、その Channel を設定します。そのトラックでノートをトリガーすると、ChooChooTracker で音を鳴らす代わりに、選択した MIDI Out デバイスに本物の MIDI が送られます。

## 15. クレジットとライセンス

ChooChooTracker は ChipNomad のフォークで、そのMIT ライセンスの方針を引き継いでいます。Braids、Plaits、Plaits-Alt、Clouds DSP、Warps 由来の MME DSP、stmlib のコードは、Mutable Instruments のオープンソースのリリースから派生しており、それぞれに適用される MIT の表示が付いています。Plaits-Alt は、lylepmills/eurorack の Plaits Lab フォークから取得されたもので、保持されているソースの表示が適用されます。aChChid エンジンは、Robin Schmidt による Open303(copyright 2009)を、MIT ライセンスのもとで使用しています。Bogie と Sintered は、独自のネイティブ実装です。MIDI の入出力は、Gary P. Scavone による RtMidi を、その MIT 風のライセンスのもとで使用しています。正確なクレジットについては、同梱のライセンスファイルを参照してください。

## トラックのインサートエフェクト (Track insert effects)

8 つのトラックにはそれぞれ、直列の 2 つのスロット **TF1 → TF2** があります。Instrument から、いつもの Shift+Up のジェスチャーで MOD を開き、もう一度 Shift+Up で **F: Insert
FX** を開きます。Shift+Down で MOD に戻ります。OPT+Left/Right でトラック(1-8)を選べ、インストゥルメントのセレクターは変わりません。モジュールのヘッダーは、既存のセレクターを開きます。バイパスは、モジュール、設定した値、オートメーションを保持します。パラメーターはバイト値で、左の列が 1-4、右の列が 5-8 です。コンテキストのテキストには、完全な名前と、デコードされた値が表示されます。古いプロジェクトは、両方のスロットが OFF で読み込まれます。

ナビゲーション表示は、Insert FX や instrument pool を含む、インストゥルメントのすべての画面で F-M-I-P の列全体を表示し続け、現在の画面をハイライトします。

| モジュール | パラメーター(順番) |
| --- | --- |
| Work Compressor | Threshold, Attack, Release, Makeup, Ratio, Detector source, Detector filter, Mix |
| Airwindows Distortion | Input, Mode, Output, Mix |
| Airwindows StereoDoubler | Detune, Mix |
| TAPESCAM | Input, Drive, Color, Wobble, Tone, Output |
| OTT (Rui-727) | Depth, Time, Upward, Downward, Input, Output |
| Chorus | Rate, Depth, Tone, Mix |
| Flanger | Rate, Depth, Feedback, Mix |
| Phaser | Rate, Depth, Feedback, Mix |
| Rotary | Speed, Depth, Drive, Mix |
| Saturation | Drive, Tone, Level, Mix |
| Bitcrusher | Bit depth, Rate reduction, Tone, Mix |
| Destruction | Mode, Amount, Tone, Mix |
| Parametric EQ | Low gain, Low frequency, Mid gain, Mid frequency, High gain, High frequency |

連続的なコントロールは、有効なゼロと最大値の FF を含めて、00-FF を使います。双極性のコントロールは、80 が正確なニュートラルです。Distortion のモードは、00 Density、01 Drive、02 Spiral、03 Mojo、04 Dyno です。Compressor のレシオ 00-07 は、1.5、2、3、4、6、8、16、20:1 です。ディテクターのソース 00-02 は、ステレオ入力、左、右です。Detector filter は 80 がニュートラルで、それより下はローパス、上はハイパスです。外部またはトラック間のサイドチェーンは用意されていません。どちらのスロットにも、任意のモジュールを入れられ、同じモジュールを繰り返しても、それぞれ独立しています。
Chorus、Flanger、Phaser、Rotary は、穏やかなモジュレーションのデフォルトを使います。Rotary Speed は、**00-FF** の全範囲を使います。**00 = 0.01 Hz**(100 秒で 1 回転)、**FF = 25 Hz**(以前の Chaos の最大値)です。指数的な間隔により、遅い LFO の動きを、より細かく制御できます。新しい Rotary インサートのデフォルトは **8F** で、約 0.8 Hz です。これは、4 つの離散的な速度の値を置き換えます。既存の Rotary の設定と F11/F21 の速度オートメーションは、新しいスケールに合わせて調整し直す必要があります(以前の Slow/Fast/Hyper/Chaos は、おおよそ **8F/CB/E7/FF** に相当します)。ほかのパラメーターは変わりません。
Bitcrusher のビット深度は 4 から 16 ビット、レートリダクションは 1x から 32x の範囲です。Destruction のモードは、Fold、Clip、Crush です。
Saturation と distortion には、未処理の信号とのバランスを取るための、出力レベルまたは mix のコントロールがあります。
Parametric EQ は、60-500 Hz と 2-14 kHz に 24 dB のブースト/カットのシェルフを持ち、250 Hz-5 kHz に Q 固定 0.9 のベルを持ちます。ゲインのコントロールは 80 がニュートラルで、3 つすべてがニュートラルのとき、完全なバイパスになります。アクティブな EQ は、フルスケールを超える部分で透明なソフトニーを使い、極端なブーストを抑えるため、最大 1.5 に達します。

トラックのレベルと tilt EQ はインサートの前にあるため、どちらも、コンプレッションとディストーションに入る信号に影響します。トラック上のすべてのボイスとコードのノートは、1 つのインサートチェーンに送られます。リバーブとディレイのセンドは、どちらもその出力を受け取ります。共有エフェクト、リターン、マスターのコントロール、ミュート/ソロは、これまでの動作を保ちます。インサートは、外部の MIDI デバイスからのオーディオは処理しません。

インサートのコマンドは、TF1 には **F11-F18**、TF2 には **F21-F28** を使います。roll の FX 選択と Phrase/Table のポップアップには、選択したトラックの設定済みインサートで使われるパラメーターだけが表示されます。ポップアップは、それらを **TF1: エフェクト名** と **TF2: エフェクト名** としてグループ化し、OFF のスロットは非表示になります。バイパス中のインサートも、編集できます。
Phrase と Table の FX ポップアップでは、説明は、選択したトラックのインサートスロットに従い、モジュール、パラメーター名、デコードされた範囲の両端、保存されたベース値を表示します。モジュールを変更したために使われなくなった既存のソングのコマンドは保持され、そのピッカーを開くと、利用可能なコントロールから始まります。
値を編集している間、下部のヒントには、デコードされた値と単位が表示されます。
Phrase や Table のどの FX 列も、どちらのスロットも指定でき、Phrase のグリッドは 3 つの列を保ちます。これらの絶対的なランタイム値は、ノート、インストゥルメント、フレーズ、チェーン、通常のループをまたいで持続します。新しい再生や強制停止で、リセットされます。F ページでベース値を編集すると、そのパラメーターの上書きだけが消去されます。MOD は、そのオフセットを保存せずに、実効的なベース/オートメーションの値に作用します。新しいモジュールを選ぶと、デフォルトが復元され、そのスロットの上書きが消去されます。バイパスは、短いフェードのあとに処理を停止しますが、既存のオートメーションは保持します。

**アドレスは、名前付きのエフェクトではなく、トラックのスロットとパラメーターの位置を指します。** 別のトラックで再利用されたフレーズは、そのトラックのモジュールを使います。モジュールを変更すると、コマンドの意味が変わることがありますが、コマンドは書き換えられません。OFF や未使用のアドレスは、安全に何もせず、保存された Phrase/Table のデータの中にそのまま残ります。

インストゥルメントの MOD セレクターには、Insert FX のカテゴリーが加わります。各インストゥルメントのソースは、そのインストゥルメントを演奏するトラックのインサートを、合成されたコードの信号を含めて制御します。同じインストゥルメントを 2 つのトラックで使うと、独立したチェーンに作用します。既存のソースのタイミング、符号付きの量、ソースの組み合わせルール、スティックモード、モーションレコーディングが適用されます。離散的なコントロールは、有効な選択肢にクオンタイズされ、制限されます。トラックが所有する新しいモジュレーションのバンクはありません。

Compressor のメイクアップは 0 dB から始まります。OTT は、およそ 25% の depth、25% の upward、50% の downward、入力 0 dB、出力 -3 dB から始まります。そのバンドのしきい値、ゲイン、クロスオーバーは、Rui-727 のネイティブのデフォルトのままで、Depth がそのウェット/ドライのコントロールです。TAPESCAM は、ネイティブの補助デフォルトを保ちます。新品/高速のテープ、ノイズ、コンプレッションはオフ、ワイドニングはオンです。drive/gain を加えるときは、既存のクリッピングのインジケーターに注意してください。スロットの遷移は、ドライのオーディオを介した、制限付きの 5 ms のフェードを使います。

保存データには、モジュール ID、バイパス、設定されたバイトが、バージョン付きの任意のセクション `Track inserts: 1,8,2` と `Master inserts: 1,2` に保存されます。ランタイムの上書きと DSP の履歴は保存されません。
インサートを有効にした保存データを古いビルドで開く前に、バックアップを取っておいてください。DSP のクレジット、ソースのリビジョン、改変は、`chipnomad_lib/external/insert_fx/SOURCES.txt` にあり、MIT の表示の全文は `licenses/INSERT_FX.txt` に同梱されています。

48 kHz の R36H では、1 つのトラックで測定した 2 つのインサートのペアは、シンセと共有エフェクトのコストを除いて、リアルタイムの約 4-5%(Compressor)、6%(Distortion)、18%(Doubler)、16%(TAPESCAM)、24%(OTT)を要しました。Doubler、TAPESCAM、OTT の 16 個のアクティブなインスタンスは、リアルタイムを超えました。オーディオレートのモジュレーションは、さらにコストを増やします。まず少数のインサートから始めて、オーディオの過負荷を確認し、使っていないスロットはバイパスしてください。利用できる 16 の位置は、CPU の予算を保証するものではありません。

Insert ページは、ボタンを離したあとも、選択したフィールドのヒントを表示し続けます。一時的な通知が、その場所を取ることもあります。モジュールセレクターには、各モジュールの名前の横に、エフェクトのタイプとソースのプロジェクトが表示されます。

### ネイティブの OPLL と VRC7 のインストゥルメント(開発中)

Instrument Type のセレクターには、**OPLL / MSX**(YM2413)と **VRC7**(DS1001)を含む FM グループがあります。それぞれ、スクロールする Bank / Preset のリストに **73 のプログラム** を備えています。元の 15 の音色、emu2413 の YM2413/VRC7/YMF281B のテーブルからの 40 の追加の異なる音色、ChooChoo が作った 18 の 2 オペレーターのプログラムです。同じ音色のバイトの完全な重複は、各エンジン内で省かれます。追加のパレットは、チップのプログラマブルな音色スロットを使い、物理的な ROM を拡張するものではありません。プログラム 0 は、カスタムの音色を示します。EDIT + 左/右で、バンクフィルター内の前または次のプリセットを選びます。Fine ct は、チューニングを -100 から +100 セントで調整します。

プログラムのリストでは、EDIT + PLAY でハイライトされた音を試聴でき、ボタンを離すと止まります。EDIT で確定、OPT でキャンセルです。閲覧や試聴で、インストゥルメント、テーブル、ソングが変わることはありません。通常の Instrument ページの試聴のジェスチャーは、選択後も引き続き動作します。ネイティブチップのエンベロープが attack/release を供給し、オプションの Amp env は、ソフトウェアの ADSR を加えます(下の「ネイティブチップのコントロール」を参照)。完全なオペレーターエディターはありません。

新しいインストゥルメントは、8 つのネイティブな音色バイト、バンク/名前、プログラム、ファインチューニングを、ソング/インストゥルメントのファイルに保存します。これらのタイプを含むファイルは、フォーマット 7.0 を使い、このビルド以降が必要です。それ以前のフォーマットは引き続き読み込めます。これらのタイプを含まないソングは、これまでどおり 5.0 で保存されます。リズムのプログラムは見送られています。拡張されたライブラリーは、ホストで検証されています。人による試聴と、携帯機での新たな確認は、まだ残っています。

### AdLib / OPL2 と OPL3(開発中)

FM には、AdLib / OPL2(YM3812)と OPL3(YMF262)も含まれます。Bank は工場出荷のリストを絞り込み、Preset はカテゴリーのグループと All ビューを開きます。EDIT + PLAY は選択前に試聴し、EDIT は選択、OPT はキャンセルです。Preset 上での EDIT + 左/右は、前または次の一致するエントリーを読み込みます。Fine ct は、ローカルのチューニングを調整します。Mode は、2 オペレーター、4 オペレーター、Dual voice を表示します。OPL2 は、互換性のない OPL3 のパッチを隠し、OPL3 は、共有の 2 オペレーターのコレクションを演奏できます。

Bank と Preset のポップアップのタイトルは、現在のエンジンを示します。エンジンやインストゥルメントのスロットを切り替えると、互換性のある AdLib と OPL3 のエンジン間の切り替えも含め、バンクフィルターは **All banks** にリセットされます。同じスロット内でポップアップから戻ったときは、選んだフィルターが保たれます。DX7 バンクのインポートをキャンセルすると、以前のフィルターが復元されます。

プリセットの確定は、ボタンを離したときに行われた編集も、次の UI/オーディオのティックに反映します。再生中のソングは、そのパッチを受け取るために、別のボタン操作やトランスポートの再起動を必要としなくなりました。出力は、設定されたオーディオバッファーと、エンジンのエンベロープ/再トリガーの動作に、引き続き従います。

工場出荷のコレクションには、The Fat Man 2-op、The Fat Man 4-op、DMXOPL3 からの 697 のソースエントリーがあり、589 の正規化された固有のパッチがあります。エイリアスは、ソースの名前とクレジットを保持します。ソース固有のオペレーターレベル、LFO の深さのフラグ、ノートのオフセット、固定のパーカッションのピッチ、デュアルボイスのチューニングは保たれます。トラッカーのボリュームは、ソフトウェアの振幅を使い、元の MIDI プレーヤーのボリュームカーブやベロシティオフセットの方針は再現しません。ソースのリリースの長さの推定値が、持続するノートを打ち切ることはありません。一部のエフェクトには、遅いアタックがあります。短いクリックで明らかになることを期待せず、Seashore を押し続けてください。

工場出荷のアセットは、既存のインストゥルメントライブラリーと並んで `instruments/chips` にあり、表示は `licenses/chip-banks` にあります。プリセットの選択は、スロットのテーブルとトラックが所有するインサートを変更しません。新しく保存されるファイルは 7.0 を使い、完全な音色を埋め込みます。工場出荷のオーディオは、ホストと ARM64 で機械的にテストされており、人による試聴は、まだ残っています。

### Sega PSG と Game Boy のネイティブインストゥルメント(開発中)

CHIP には、Sega PSG、GB Pulse、GB Noise が含まれるようになりました。Sega は、NTSC のマスタークロックと、トーンチャンネル由来のノイズを含む、16 ビットのノイズフィードバックを使います。そのデフォルトの **Bass range: Extended** は、チップの約 109 Hz という分周器の限界より下で演奏できるよう、必要に応じて仮想クロックを下げます。これにより、A-2、G-2、F-2 が区別されたままになります。元の範囲では、低いノートが分周器の限界に収束するため、**Chip** を選んでください。固定レートのノイズは元のクロックを保ち、トーン由来のノイズは、拡張されたピッチに従います。古い Sega インストゥルメントは、Extended を有効にして読み込まれ、この設定はインストゥルメントとともに保存されます。
GB のインストゥルメントは、DMG のパルス/ノイズレジスターを使い、Game Boy のウェーブチャンネルは公開されていません。作成されたプリセットのリストには、それぞれ **24、24、28** のプリセットが含まれています。追加されたのは、連結/周期的な Sega のノイズ、GB のピッチスイープ、短いパーカッション、金属的なノイズ、ドローン、ライザーです。これらはオリジナルのプログラムであり、ゲームから抽出した音ではありません。
このページには、該当する場合、ネイティブのモード/デューティ/幅、エンベロープ/スイープ/ノイズのコントロールと、ソフトウェアの振幅 ADSR があります。これらは、バージョン 6 のネイティブファイルに保存されます。ARM64 での自動のパフォーマンス/オーディオのチェックは、報告された負荷の範囲内で合格しており、人による試聴は、まだ残っています。

### DX7 FM(開発中)

**Type → FM → DX7 FM** を選びます。DX7 は、Arcade / YM2151 の次の、7 番目のエントリーです。DX7 FM は、6 オペレーターの MSFA コアを使います。既存の FM ページには、共通のインストゥルメント設定に加えて、Bank、Preset、Fine ct があります。プリセットの閲覧は、バンク/カテゴリーのリストを使います。EDIT+PLAY を押し続けると、ハイライトされた音を聴けて、離すと試聴が止まります。EDIT だけなら、離したときに確定し、OPT でキャンセルします。音を読み込むと、トラッカーのテーブルやトラックのインサート FX を変更せずに、そのパッチ全体がコピーされます。

工場出荷のカタログには、現在、**67 の異なる DX7 のパラメーターパッチ**があります。OpenDX7 のオリジナルの音楽的な音が 31、YSE の CC0 の固有の音が 4(その 32 のバンクスロットは、この 4 つを異なる名前で繰り返したものです)、ChooChoo が作ったパッチが 32 です。ここでの「オリジナル」は、このプロジェクトのために作成されたパラメーターのプログラムを意味し、Yamaha の元の工場出荷のコンテンツを意味するわけではありません。YSE は、人為的に異なる 32 の名前ではなく、4 つの音として提供されています。
カテゴリーは、レビューされたサウンドデザインの意図を表しています。曖昧な名前は Unsorted のままです。数値による演奏可能性のチェックは合格しており、聴感による受け入れは、まだ残っています。再配布が許可された 1,000 の音という別の目標は、達成されていません。

永続的な個人ライブラリー用に、`.syx` ファイルを、既存のインストゥルメントライブラリーの隣にある **`instruments/banks/dx7/`** に置きます。サブフォルダーに対応しています。**DX7 → Bank** を開くと、各ファイルが名前付きのバンクとして表示され、Preset での閲覧の準備が整います。ファイルを追加または削除したあとは、Bank を開き直してください。変換や Load Instrument の手順は不要です。標準的なオリジナルの DX7/TX7 のバンクには、**32 のボイス**が含まれます。4 つのバンクメッセージを持つファイルは、4 つの番号付きバンク(合計 128 ボイス)として表示されます。単一ボイスのファイルも受け付けられます。ネイティブアプリはこのフォルダーを読み、ブラウザー版は、コンピューター上の任意のフォルダーではなく、仮想ファイルシステムを読みます。

不良またはサポートされていないファイルは、画面上にその数が表示されてスキップされ、有効なバンクは引き続き利用できます。スキャンは、2,048 ファイル、1 ファイルあたり 1 MiB、合計 64 MiB、60,000 ボイス、8 階層のネストしたフォルダーに制限されます。シンボリックリンクは無視されます。選択したパッチはインストゥルメントが所有するため、そのソースバンクを削除しても、保存されたソングは変わりません。閲覧用のライブラリー全体は、このフォルダーにとどまり、各プロジェクトにまとめてコピーされることはありません。

LOAD INSTRUMENT は、オリジナルの DX7/TX7 の単一ボイスと 32 ボイスのバンクの `.syx` ダンプも受け付けます。サポートされるメッセージの、制限付きのシーケンスも含みます。インポートしたバンクを同じ FM ブラウザーで開く前に、フレーミング、バイト数、7 ビットデータ、チェックサム、パラメーターの範囲、ファイルサイズを確認します。パッチを選ぶと確定し、キャンセルすると、現在のソングのインストゥルメントが保たれます。この直接インポートのショートカットは、セッションの間、閲覧のリストを保持します。永続的な閲覧には、上のバンクフォルダーを使ってください。選択または編集したパッチを残すには、ソングまたは `.cni` を保存してください。ヘッダーのないダンプ、不正なチェックサム、DX7II のパフォーマンス/拡張、その他の Yamaha のファミリーは拒否されます。インポートが、外部の機器に MIDI メッセージを送ることはありません。

CNI とプロジェクトのバージョン 6 は、155 バイトの元のボイスバイトすべて、完全な表示名、ネイティブのストライクベロシティ、ファインチューニング、ソースの識別情報を保存します。ソングは、再び開くのに外部のバンクを必要としません。古い ChooChoo のリリースは、これらのバージョン 7 のファイルを読めません。既存のものだけのプロジェクトは、これまでどおりバージョン 5 で保存されます。ネイティブのベロシティのデフォルトは 100 で、トラッカーのボリュームは合成後のゲインであり、エンベロープを再び叩き直すことはありません。オペレーターのエンベロープ、固定周波数モード、キーボードスケーリング、ピッチエンベロープ、LFO は、パッチのネイティブな動作のままです。オプションの共通の FM 振幅 ADSR は、オペレーターのエンベロープを置き換えずに、その合成出力を整えます。

各トラックのパートには、1 つの LFO と、4 つの別々に所有されたコードボイスのスロットがあり、既存のトラッカーのコード/置き換えの方針に一致しています。トラックは、ノートの状態を共有しません。ノートオフはネイティブのエンベロープをリリースし、cut/panic はそれらを消去します。スカラーの MSFA コアは、固定の内部 44.1 kHz で 64 サンプルの量子を使い、出力レートへのストリーミング FIR を備えます。ルックアップテーブルは、オーディオのレンダリングの外で一度だけ初期化されるため、同時に動作するオフラインとライブのレンダラーが、互いのレートを変えることはありません。イベントは、次の内部量子(最大 1.45 ms)で反映され、そのあとに FIR の約 0.25 ms の群遅延が続きます。バッファーされたサンプルは、コールバックをまたいで保持されます。これは MSFA Modern の系譜であり、DX7 のハードウェアとビット単位で同一であるとか、Dexed Mark I のエミュレーションであるといった主張ではありません。DX7 は、**ソング全体で 16 のアクティブなノート**に制限され、リリースのテールも含まれ、トラックごとに 4 つの専用のコードスロットが保持されます。予算を超えると、まずリリースのテール、次に最も静かな保持中のノート、最後に新しいアタックが取り除かれます。アタックが同じ場合は、トラック間でルートのノートが、コードの拡張より先に保持され、スロット/トラックによる安定した決め方が使われます。この方針は、すべてのプラットフォームに適用されるため、同じソングが、同じ制限付きのノート割り当てになります。ほかのインストゥルメントのポリフォニーは変わりません。プリセットの試聴は、再生中は無効です。この上限は、R36H の測定から選ばれ、混合再生で検証されました。

#### FM オペレーターエディター

Genesis FM、Arcade FM、OPL2、OPL3、OPLL、VRC7 のインストゥルメントには、Fine ct の右に **EDIT** ボタンがあります。これは、パッチのパラメーターの表を開きます。

- Genesis FM / Arcade FM: algorithm、feedback、pan、AMS、PMS、オペレーターのマスク、LFO の設定、そして 4 つのオペレーターそれぞれの MUL、DT、TL、KS、AR、D1R、D2R、RR、D1L、さらに SSG(Genesis)または DT2 と AM(Arcade)。
- OPL2 / OPL3: ボイスごとの feedback、connection、pan、deep vibrato と tremolo、そしてオペレーターごとの MUL、TL、AR、DR、SL、RR、waveform、KSL、VIB、TRM、SUS、KSR。OPL3 では、ここでモード(2op、4op、dual)を変更できます。
- OPLL / VRC7: カスタムの音色のレジスター(feedback、MUL、TL、KSL、AR、DR、SL、RR、waveforms、AM、VIB、EG、KSR)。ROM のプリセットを編集すると、「Custom」になります。

Left/Right と通常の編集キーで値を変更します。インストゥルメントはいつもどおり鳴り続けるため、変化を聴けます。ステータスバーには、カーソル下のパラメーターの説明が表示されます。OPT または Left+Shift でインストゥルメント画面に戻ります。DX7 と SID には、オペレーターエディターがありません。

Genesis FM(YM2612)と Arcade FM(YM2151)は、同じ FM の Bank/Preset ブラウザー、EDIT+PLAY の試聴、確定/キャンセル、ファインチューンのコントロールを使うようになりました。Genesis には、元の 24 と、NeoSoundFonts の CC0 の 16-Bit FM Music Station バンクからの、対応する 49 のメロディックなプログラムを合わせた、**73 のプリセット**があります。Arcade には、元の 24 と、YMulator-Synth の GPLv3 のコレクションからの、対応する音の出る 57 のプログラムを合わせた、**81 のプリセット**があります。元の ChooChoo のペアは、基になるレシピを共有し、新しいソースのコレクションは、別のパレットを提供します。これらは名前付きのサウンドデザインのコレクションであり、特定のゲームのサウンドトラックの再現を主張するものではありません。サポートされていないノートのオフセット、固定のパーカッションのキー、アーケードのノイズの設定、無音のソースのプログラムは、`expansion-manifest.json` に除外として記録されています。それらの完全な 4 オペレーターのパッチ、エンベロープ、LFO、ステレオ、チューニングの設定は、バージョン 6 のインストゥルメントとソングの中に保存されます。ネイティブチップのエンベロープが release を制御し、通常のトラッカーのゲインとピッチは、それを再び叩き直しません。Genesis の DAC 出力は、20 Hz の DC ブロッカーを使います。ノイズモードと、チャンネル 3 の特殊周波数モードは、このインストゥルメントの実装の対象外です。

ローカルの外部バンクには、`tools/chip_banks/import_bank.py SOURCE --output
NEW_DIRECTORY --writer tracker/build/tests/chip_factory` を使います。厳密な 42 バイトの TFI、VOPM の OPM テキスト、検証済みの WOPLX フォーマット、オリジナルの DX7 SysEx を受け付けます。生成された `.cni` ファイルは、Load Instrument から読み込みます。ユーザーのインポートは、配布可能な工場出荷のライブラリーとは別に保管されます。ノイズが有効、ノイズ周波数のデータがゼロ以外、または部分的なパンニングの OPM ファイルは、説明付きで拒否されます。VOPM のパンの値 0/64/127 は、左/両方/右になります。バイナリーの WOPL には対応していません。
共有の FM カタログには、**1,064 のエントリー**があります。OPL が 697、DX7 が 67、OPLL/VRC7 が 146、Genesis が 73、Arcade が 81 です。さらに 76 のファイルが、通常のファイルブラウザーを通じて Sega/Game Boy のプリセットを公開しており、合計で **1,140 の同梱ネイティブプリセット**になります。ソースのリビジョン、ハッシュ、完全な表示、元のソースデータは、新しいコレクションとともに、`licenses/chip-banks/expansion` にあります。

### 持ち運び可能な工場出荷コレクションと USER プリセット

ネイティブチップのインストゥルメントは、**Bank:** で、ALL、同梱のコレクション、USER のいずれかを選びます。**Preset:** は、その選択の中から音を選びます。どちらの行でも、EDIT を押し続けながら Left または Right を押すと循環し、EDIT を短くタップすると、そのセレクターが開きます。

同梱のコレクションは、`instruments/FACTORY/` の下にある ZIP パックです。USER ファイルは、`instruments/USER/<engine>/` の下に置きます。`dx7`、`opll`、`vrc7`、`opl2`、`opl3`、`genesis`、`arcade`、`sid`、`sega`、`gb-pulse`、`gb-noise` のいずれかです。フォルダーを直接閲覧するか、互換性のあるプリセットの ZIP をそこに置きます。ZIP は、ディスク上でそのままの形で保たれます。これらのフォルダーはすべて、互換性のある `.cni` ファイルを受け付けます。CNI は、ChooChoo/ChipNomad の持ち運び可能なインストゥルメントフォーマットであり、チップメーカーの規格ではありません。USER ブラウザーは、ZIP の中も含めて、次のソースフォーマットも読み込みます。

| USER フォルダー | 追加のフォーマット |
| --- | --- |
| `dx7` | Yamaha DX7/TX7 の `.syx` の単一ボイスと 32 ボイスのバンク |
| `genesis` | `.tfi`、DefleMask の `.dmp`、Furnace の `.fui` |
| `arcade` | VOPM の `.opm` バンク、DefleMask の `.dmp`、Furnace の `.fui` |
| `opl2`, `opl3` | `.wopl`、`.opli`、`.woplx`、`.sbi`、Furnace の `.fui` |
| `opll`, `vrc7` | Furnace の `.fui` のカスタムパッチと、固定の ROM の選択 |
| `sega`, `gb-pulse`, `gb-noise` | Furnace の `.fui`、DefleMask の `.dmp` |
| `sid` | GoatTracker 2 の `.ins`(GTI5)、Furnace の `.fui` |

バンクは、互換性のあるボイスに展開されます。サポートされていないファイルや機能は、理由を報告します。混合バンク内の互換性のないボイスは除外されますが、そのソースの番号は変わりません。読み込みはトランザクション方式で、拒否されたプリセットは、現在のインストゥルメントをそのままにします。ソースのプリセットは、インストゥルメントのトラッカーのテーブルを空のものに置き換えますが、DX7 の SysEx は、既存のテーブルを保ちます。CNI は、保存されたテーブルを復元します。読み込まれたパッチはソングが所有し、ソースのパックを移動または削除しても、動作し続けます。

WOPL のバンクには、明示的な空のフラグのない、未使用のスロットが含まれることがあります。ブラウザーは、アクティブなオペレーターが完全に減衰していて、アタックのない、名前のないスロットを省きます。名前のない演奏可能なボイスは、ソースの 0 から始まるプログラム番号とバンク番号を使って、`Program N [Bbank]` または `Drum N [Bbank]` として利用できるままです。名前のない単一の OPLI インストゥルメントは、そのファイル名を使います。名前の付いた無音のパッチは保持されます。

Furnace の対応は、レガシーな単一インストゥルメントのバージョン 29-112 と、機能ベースの `FINS` のバージョン 127-251 をカバーします。DefleMask の対応は、バージョン 11 の OPN、OPM、Sega PSG、Game Boy のインストゥルメントをカバーします。これらはインストゥルメントのインポートであり、完全なトラッカーのプレーヤーではありません。アニメーションする FM/オペレーターのマクロ、ソースのソングの FM LFO の設定、サンプル、Game Boy のハードウェアコマンドのシーケンス、相対的な SID のパルス/フィルターのマクロ、SID の ring/sync の依存関係は、現在は拒否されます。定数の OPLL の ROM の選択には対応しており、VRC7 は、その選択に自身の ROM を使います。SID-Wizard の `.swi` と、SID の音楽ファイル(`.sid`)は、このビルドではインストゥルメントのインポートではありません。

サポートされる PSG/GB/SID のシーケンスは、パッチ内に保存され、Furnace/DefleMask では 60 Hz、GoatTracker では 50 Hz で再生されます。これらのファイルは、完全なソングの再生設定を持っていません。そのソング固有のティックレート、チャンネルのルーティング、ハードリスタートの動作、互換性の設定が必要な場合は、元のトラッカーを使ってください。Sega PSG では、デューティのマクロがノイズボイスを選び、ない場合、インポートはトーンボイスを使います。Game Boy のファイルは、意図したパルスまたはノイズのフォルダーに置く必要があります。インポートされたシーケンスは、現時点では埋め込まれた再生データのままです。インストゥルメントのページは、ソースのトラッカーのテーブルではなく、基本的なパラメーターを編集します。

USER のプリセットの循環は、ファイル、フォルダー、バンク、ZIP パックをまたいで、両方向に続き、端で折り返します。USER ブラウザーを開き直すと、現在の選択に従います。ALL には、カテゴリーのあるエンジンについて、Unsorted の下に USER の音が含まれます。USER は、別の最上位の選択肢のままです。Sega PSG と Game Boy は、フラットな ALL/Factory のリストと、階層的な USER ブラウザーを使い、Unsorted パネルはありません。`instruments/banks/dx7/` にある古い DX7 のファイルは、USER から引き続きアクセスできます。

エンジンには、互換性のある同梱のコレクションだけが表示されます。Factory Presets は、選択したエンジンの同梱の OPLL/VRC7 の音色セットを組み合わせ、DX7 は、ChooChoo と YSE のオリジナルを組み合わせます。ダウンロードした名前付きのコレクションは、別のままです。Fat Man 2-op は OPL2 の下に、Fat Man 4-op は OPL3 の下に表示されます。互換性のある OPL2 の CNI ファイルは、OPL3 の USER フォルダーでも引き続き使えます。

ネイティブエンジンの出力は、プリセットごとの正規化ではなく、測定された固定のゲイン補正を使います。そのため、既存のネイティブインストゥルメントのソングは、異なるレベルで鳴ることがあります。保存したミックスのバランスを見直してください。キャリブレーションの方法と範囲は、`scripts/README_MEASURE.md` に記載されています。

`native-chip-audition.cct` は、元の 13 の工場出荷のバンクを順に聴ける、短い試聴を提供します。各セクションは、それぞれ異なる所有のインストゥルメントを使うため、プリセットのフォルダーを削除しても動作します。より長い、Git で無視されるバンクの WAV と、測定されたレベルは、`docs/chip-preset-auditions.tsv` に一覧があり、主観的な試聴は、まだ残っています。

### ネイティブチップのコントロール (Native chip controls)

ネイティブインストゥルメントの波形プレビューは、そのコントロールが再描画されるときに更新されます。FM インストゥルメントは、オプションの Amp env カーブを重ねられます。SID は、バンクやプリセットを閲覧しているときも含めて、FM 専用のそのオーバーレイなしで、波形のプレビューを保ちます。

7 つの FM エンジンすべてが、**Bright**、**Feedback**、**Amp env** を備えています。Bright は -63 から +63 までで、ゼロはパッチをそのまま保ちます。キャリアのレベルを保ったまま、モジュレーターのオペレーターのレベルを変えます。聴こえる効果は、アルゴリズムによって異なります。Feedback のデフォルトは **Preset** で、0-7 でネイティブのフィードバックを上書きします。これらのコントロールは、保存されたネイティブのオペレーターのバイトを書き換えません。

Amp env のデフォルトは **Bypass** です。**ADSR** を選ぶと、ネイティブの音の周りに、アタック、ディケイ、サスティン、リリース、シェイプが加わります。A/D/R は、共通の 0-5 秒の 2 次の範囲を使い、サスティンは、無音から最大レベルまで及びます。ネイティブのエンベロープは引き続き動作するため、このエンベロープでは、音をネイティブのリリースより長く延ばすことはできません。プリセットの閲覧では、スロットの FM のアンプと音色のコントロールが保たれます。すべての FM ボイスは、Amp env がバイパスされているときも含めて、3 ms のオンセット/再トリガーの遷移と、1 ms のトラッカーゲインの平滑化を使います。ハードカット/panic は、即座のままです。

次のフレーズの FX は、対応する Modulation とモーションレコーディングのデスティネーションとしても現れます。FX 列の値は 16 進数です。設定は、保存されたインストゥルメントを変えずに、再生に適用されます。ネイティブの GB のスイープとエンベロープのコントロールは、次のノートのトリガーでラッチされます。デューティ/幅とノイズ周波数は、ライブで変更できます。

| エンジン | FX | コントロール |
|---|---|---|
| Native FM | `OL1`-`OL6` | オペレーターの絶対的な出力レベル: OPLL/VRC7 のモジュレーターと OPL は `00-3F`、OPLL/VRC7 のキャリアは `00-0F`、Genesis/Arcade は `00-7F`、DX7 は `00-63`(0-99)。値が大きいほど出力が大きくなります。サポートされるオペレーターだけが表示されます。 |
| OPLL/VRC7/OPL2/OPL3 | `OAR`, `ODR`, `ORR`, `OSL` | オペレーター 1 のアタック、ディケイ、リリース、サスティンの減衰、`00-0F`。 |
| OPLL/VRC7/OPL2/OPL3/Genesis/Arcade | `OMU 00-0F` | オペレーター 1 の周波数の乗数。 |
| Genesis/Arcade | `LFR` | ネイティブの LFO のレート: Genesis は `00-07`、Arcade は `00-FF`。 |
| Arcade | `LAD`, `LPD 00-7F` | 別々の LFO の振幅とピッチの深さ。 |
| Genesis/Arcade | `LAS`, `LEN` | ネイティブの振幅感度 `00-03` と、LFO の有効化 `00-01`。 |
| Genesis/Arcade | `LPS 00-07` | ネイティブのピッチ感度。 |
| SID | `SAT`, `SDE`, `SSU`, `SRL 00-0F` | ネイティブのアタック、ディケイ、サスティン、リリース。時間の値は `0F` に向かって増え、サスティンは最大レベルに向かって増えます。 |
| SID | `SPR 01-10` | 1× から 16× の、サイレントパートナーの周波数。リング変調とハードシンクに影響します。 |
| すべてのネイティブ FM | `FBK 00-07` | インストゥルメントから初期化される、絶対的なネイティブのフィードバック。 |
| Amp env を有効にしたすべてのネイティブ FM、Sega/GB | `EAT`, `EDC`, `ESU`, `ERL`, `ESH 00-FF` | アタック、ディケイ、サスティン、リリース、シェイプ。バイパス中の FM アンプは有効になりません。 |
| Sega PSG | `CMD 00-02`, `CNR 00-03` | トーン / ホワイトノイズ / 周期ノイズ。3 つの固定のノイズレート、またはトーン由来のレート。 |
| GB Pulse | `CMD 00-03` | ネイティブのパルスのデューティ。 |
| GB Noise | `CMD 00-01`, `CND 00-07`, `CNS 00-0D` | ノイズの幅、クロックの除数、シフト。 |
| GB Pulse | `CSP 00-07`, `CSS 00-07`, `CSD 00-01` | スイープの周期、シフト、下向きの方向。 |
| GB Pulse / Noise | `CEI 00-0F`, `CEP 00-07`, `CED 00-01` | ネイティブのエンベロープの初期レベル、周期、上向きの方向。 |

ネイティブの FX の選択では、フレーズの行の `I` 列にあるインストゥルメントを使い、`I` が空白の場合は、さかのぼって見つかったアクティブなインストゥルメントを使います。FX ポップアップには、コントロールの短い説明、現在のプリセットの値、有効なコマンドの範囲が、コンパクトなブロックで表示されます。別のネイティブエフェクトを選ぶと、その値から始まり、同じエフェクトを開き直すと、編集した値が保たれます。複数行の選択は、各行のインストゥルメントを個別に解決します。テーブルは、そのインストゥルメントのコンテキストを使います。ネイティブの値の編集は、デューティ、ノイズ、スイープ、ADSR、フィードバック、オペレーターのレベルを含め、有効な端で止まります。値は 16 進数です。たとえば、DX7 の最大値 `63` は、10 進数の 99 を意味します。

これらの FM コマンドは、絶対的なネイティブの値を使います。オペレーターのコマンドは、常にオペレーター 1 を対象とし、`OMU 03` は、その乗数 3 を選びます。DX7 のトラッカー固有のコントロールは、オペレーターのレベルとフィードバックです。Preset/Range は、その情報の色を保ち、タイトルと説明は、FM Feedback と同じ色に従います。

ライブの Modulation は、固定オペレーターのネイティブなデスティネーションの全セットを保ちます。モーションレコーディングは、コンパクトなトラッカーのリストで表されるコントロールだけを書き込み、オペレーターのパラメーターは、オペレーター 1 についてのみ記録されます。ほかのモジュレーションのデスティネーションは、ライブでは引き続き動作しますが、フレーズのコマンドは生成しません。

`SCP` と `SCT` は、8 ビットより広い SID のレジスターへの、バイトスケールのマッピングを保ちます。`SMR 01-C8`、`SWV 01-08`、`SPR 01-10` は、ネイティブのプリセットの番号付けに一致するようになりました。表示されるプリセットの値は、再生中のエンベロープや LFO とは独立した、基本の設定です。`SLE` は、ノートを再トリガーしたり、保存されたパッチを変更したりせずに、オペレーターのレベルと直接の FM パラメーターに作用します。

すべてのネイティブ FX には、フレーズの FX チューザーに、説明的なタイトル、範囲、動作があり、値のヒントもあります。`CMD` は、選択したインストゥルメントに応じて、トーン/ノイズ、デューティ、またはノイズの幅を説明します。これらのコントロールは、共有の Track、Envelope、Modulation のグループを補うものであり、エンジンのグループだけで、利用可能なフレーズ FX の全セットになるわけではありません。

Braids、Plaits、PCM、その他の対応エンジンにある、既存の共有の LP/BP/HP フィルターは、合成後のソフトウェア処理です。aChChid は、代わりに、ネイティブの 303 のフィルターの経路を使います。今回の変更では、AY やネイティブ FM にフィルターは追加されません。brightness は、FM の合成そのものを変えます。追加の処理には、トラックのインサートが引き続き使えます。

ネイティブのインストゥルメントは CNI のバージョン 7(絶対的なコマンドがある場合は 8)で、ネイティブのソングは CCT のバージョン 9 で保存されます。インポートされたシーケンスを含むインストゥルメントは CNI のバージョン 9 を、それを含むソングは CCT のバージョン 10 を使います。古いビルドは、シーケンスを含むこれらの新しいファイルを開けません。保存された FM プリセットのバイトと、インストゥルメントのページの音色の設定は、変わりません。

### ネイティブチップ向けの携帯機の負荷の目安

ソングのトラックは 8 つあり、**トラックごとに 2 つのインサートエフェクトのスロット**があります。利用できる 16 のスロットは、16 個のエフェクトを動かすのに十分な CPU を保証するものではありません。DX7 の 16 のアクティブなノートという上限は、ソング全体の、別のシンセシスの予算であり、コードとリリースのテールも、これに数えられます。

R36H での測定では、ループする 4 つの WAV トラック、Sega PSG、GB Pulse、DX7、共有センドと 4 つのインサート(2 つの Compressor、Doubler、TAPESCAM)を備えた OPL3 は、密な 8 トラックの FM アレンジメントよりも良好に動作しました。単音のバージョンは、30 秒間、48 kHz/512 フレームの測定で、レンダリングの締め切りの未達がありませんでした。4 音の DX7 コードを加えると、タイミングのスパイクが 1 回ありました。高コストなインサートを多用した密な FM のソングは、CPU の予算を超えました。ある程度の余裕を残し、既存の過負荷のインジケーターを確認し、ソングの助けになる場所にエフェクトを加えてください。アプリはすべてのトラックとスロットを保持しており、インサートの数に新たな厳密な上限はありません。測定の全体と、長時間のテストの状況は、`chip-instruments-report.md` を参照してください。

そのバランスの取れたコードのアレンジメントに対応する、70 秒間の実際のオーディオのテストは、既存の 48 kHz / 4906 フレームの設定で、レンダリングの締め切りの未達も、記録された ALSA のアンダーランもなく、合格しました。最悪のコールバックは、102.208 ms の締め切りに対して 81.819 ms でした。テストは、ヘッドルームのために、0.4 の別のマスターゲインを使いました。通常のランチャーの、ダイレクトカードの `AUDIODEV=plughw:0,0` の経路を保ってください。システムのデフォルトの共有ミキサーでは、診断用のプローブでアンダーランが発生しました。ユーザーのオーディオ設定は変更されていません。より小さなバッファーでの 10 分間のストレステストは、それでも 28 回のタイミングのスパイクを記録しました。完全な結果は、レポートにあります。

### SID インストゥルメントと Phrase FX

**CHIP → SID** を選びます。Bank には、**ChooChoo SID Originals**(32 のオリジナルのプログラム)と、**SIDkit Effects**(MIT ライセンスの 24 のエフェクト)があります。どちらも同じプリセットブラウザーを使い、選択したプログラム全体を、インストゥルメントとソングに保存します。ソングを共有するのに、外部のバンクは不要です。これらは、エンベロープとモーションのレシピを持つネイティブの SID パラメーターのプログラムであり、サンプリングされたオーディオや、完全な C64 のソングではありません。別の 12 の GoatTracker のリサーチ候補は同梱されていません。その wave/pulse/filter のテーブルには、専用のインポーター/プレーヤーが必要です。

インストゥルメントのページには、波形/パルス幅、フィルターのモード/カットオフ/レゾナンス、ネイティブの ADSR のコントロールがあります。SID は、バージョンが固定された floooh/chips の、デジタルオシレーター、エンベロープ、サイクルごとの 6581 風のフィルターを使います。代替のチップモデル、リビジョンのセレクター、追加のキャラクタープロファイルはありません。これは汎用的な近似であり、較正された R2/R3/R4/8580 のアナログモデルではありません。

各ノートには、それぞれのフィルターがあります。Ring/sync は、サイレントなパートナーオシレーターを使うため、フィルターの共有と 3 ボイスの相互作用は、物理的な SID とは異なります。携帯機には、ソング全体で 4 つの通常の SID ノートという予算があります。Ring または sync は、1 ノートあたり 2 単位の予算を消費するため、そのようなノートを 2 つ、または 1 つと通常のノート 2 つまで使えます。コードとリリースのテールも数えられます。リリースされたノートが最初に取り除かれ、新しいノートは、古い保持中のノートより優先されます。高コストなインサートやほかのシンセも、引き続きオーディオ CPU の予算を共有します。

| FX | 範囲 | 動作 |
| --- | --- | --- |
| `SCP` | `00-FF` | ネイティブの 12 ビットの幅にスケールされた、パルス幅のベース。レシピのパルスのモーションは、有効なままです。 |
| `SCT` | `00-FF` | ネイティブの 11 ビットのカットオフにスケールされた、カットオフのベース。レシピのフィルターのモーションは、有効なままです。 |
| `SRN` | `00-0F` | ネイティブのレゾナンス。 |
| `SWV` | `00-07` | Triangle、saw、tri+saw、pulse、tri+pulse、saw+pulse、tri+saw+pulse、noise。 |
| `SFI` | `00-07` | フィルターモードのビット: 1 がローパス、2 がバンドパス、4 がハイパス、0 がバイパス。 |
| `SMR` | `00-FF` | 1 から 200 Hz にスケールされた、レシピのマクロクロック。 |
| `SRG` | `00-01` | サイレントパートナーとの三角波のリング変調。 |
| `SSY` | `00-01` | サイレントパートナーとのオシレーターのシンク。 |

パルス幅とカットオフは、`SLE` に対応しています。離散的な波形、スイッチ、レゾナンス、FM のフィードバックは、有用なネイティブのステップを保ちます。より広いバイトの値でも、ハードウェアの状態が増えるわけではありません。`FBK` は、フィードバック `00-07` を直接選びます。オペレーターのレベルは、上に挙げたエンジン固有の範囲を使います。brightness とマスターの調整は、バイトの全範囲を保ちます。

### 持ち運び可能な工場出荷コレクションと USER プリセット

ネイティブチップのインストゥルメントは、**Bank:** で、ALL、同梱のコレクション、USER のいずれかを選びます。**Preset:** は、その選択の中から音を選びます。どちらの行でも、EDIT を押し続けながら Left または Right を押すと循環し、EDIT を短くタップすると、そのセレクターが開きます。

同梱のコレクションは、`instruments/FACTORY/` の下にある ZIP パックです。USER ファイルは、`instruments/USER/<engine>/` の下に置きます。`dx7`、`opll`、`vrc7`、`opl2`、`opl3`、`genesis`、`arcade`、`sid`、`sega`、`gb-pulse`、`gb-noise` のいずれかです。自分のフォルダーを直接閲覧するか、フォルダーと互換性のある `.cni` のプリセットの ZIP をそこに置きます。DX7 は、サポートされる `.syx` の単一ボイスと 32 ボイスのバンクも、ZIP の中を含めて受け付けます。ZIP は、ディスク上でそのままの形で保たれます。WOPL/WOPLX の直接の読み込みには対応していません。互換性のある CNI のプリセットを使うか、サポートされるソースのフォーマットを、先にオフラインで変換してください。

USER のプリセットの循環は、ファイル、フォルダー、バンク、ZIP パックをまたいで、両方向に続き、端で折り返します。USER ブラウザーを開き直すと、現在の選択に従います。ALL には、カテゴリーのあるエンジンについて、Unsorted の下に USER の音が含まれます。USER は、別の最上位の選択肢のままです。Sega PSG と Game Boy は、フラットな ALL/Factory のリストと、階層的な USER ブラウザーを使い、Unsorted パネルはありません。`instruments/banks/dx7/` にある古い DX7 のファイルは、USER から引き続きアクセスできます。

エンジンには、互換性のある同梱のコレクションだけが表示されます。Factory Presets は、選択したエンジンの同梱の OPLL/VRC7 の音色セットを組み合わせ、DX7 は、ChooChoo と YSE のオリジナルを組み合わせます。ダウンロードした名前付きのコレクションは、別のままです。Fat Man 2-op は OPL2 の下に、Fat Man 4-op は OPL3 の下に表示されます。互換性のある OPL2 の CNI ファイルは、OPL3 の USER フォルダーでも引き続き使えます。

ネイティブエンジンの出力は、プリセットごとの正規化ではなく、測定された固定のゲイン補正を使います。そのため、既存のネイティブインストゥルメントのソングは、異なるレベルで鳴ることがあります。保存したミックスのバランスを見直してください。キャリブレーションの方法と範囲は、`scripts/README_MEASURE.md` に記載されています。
